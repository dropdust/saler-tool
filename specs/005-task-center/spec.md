# Feature Specification: 统一任务中心与任务后台化

**Feature Branch**: `005-task-center`

**Created**: 2026-10-14

**Status**: Draft

**Input**: 用户描述："启动挖掘任务后，一直前台运行。这个可以作为后台任务么？不影响用户使用其它功能。切到后台任务，需要有地方显示任务运行状态。"（经澄清确认：范围为全部任务类型统一任务中心 + 对话框类任务支持转后台；常驻入口形态为顶栏徽标 + 任务抽屉）

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 任务运行状态随处可见、可离开页面 (Priority: P1)

用户启动客户线索挖掘（或群发、AI 扩充、导入导出、备份等任一长任务）后，希望照常使用其它功能——去种子库整理知识图谱、审核线索、调整设置——而不是被"钉"在启动任务的页面上。当前仅个别页面（挖掘任务页、计划监控页）在页内展示任务进度，离开页面后状态即不可见，回到页面还需手动点开某条记录才能继续看。用户需要：应用顶栏常驻任务入口（带运行中数量），任意页面一点即可展开任务抽屉，看到所有正在执行的任务：跑到哪个阶段、已完成多少、耗时多久，并能直接暂停、恢复、取消或跳转到相关页面查看详情；刷新页面或重新进入应用后，仍在执行的任务的状态展示自动恢复，无需任何手动找回操作。

**Why this priority**: 这是本次请求的核心价值切片——把"必须盯着"变成"随时可看"，让长任务真正后台化、不占用用户的操作注意力。没有它，其余目标（对话框转后台、终态提醒）都缺少承载进度的"家"。

**Independent Test**: 启动一次挖掘任务后立即切换到其它任意页面，核对顶栏徽标出现运行中计数；展开抽屉核对进度/阶段/耗时持续更新；执行暂停/恢复/取消核对与页内监控口径一致；刷新页面核对进度自动恢复显示；对照页内监控卡片核对两处状态无矛盾。

**Acceptance Scenarios**:

1. **Given** 用户启动了一次挖掘任务，**When** 用户切换到任何其它页面，**Then** 顶栏常驻入口显示运行中任务数量且实时更新，抽屉内可见该任务的名称、状态、进度与当前阶段，无需回到挖掘任务页。
2. **Given** 任务抽屉已展开且某任务正在运行，**When** 用户点击暂停，**Then** 任务暂停且抽屉、页内监控两处状态一致；点击恢复后继续执行，进度不回退。
3. **Given** 任务正在运行，**When** 用户刷新页面或重新进入应用，**Then** 任务中心自动恢复展示该任务及最新进度，用户手动操作步骤为 0 次。
4. **Given** 抽屉内可见某任务，**When** 用户点击跳转，**Then** 一键到达该任务对应的详情/结果页面（如挖掘任务页、计划监控页、待审核列表）。
5. **Given** 用户离开期间有任务已完成，**When** 用户打开任务抽屉，**Then** 可在"最近完成/失败"分组中回看其结果摘要。

---

### User Story 2 - 对话框类任务「转入后台」 (Priority: P2)

用户通过模态对话框启动的任务（AI 种子扩充、种子翻译、内容起草、主题级多语言生成）目前必须开着对话框等待：模态遮罩挡住整个应用，关掉对话框又看不到进度、重开还可能把状态重置、误以为可以再次提交。用户需要：这类任务一律可以"转入后台"——关闭对话框，任务继续执行；进度统一在任务中心查看；任务进行期间重开同一对话框时，看到的是这个进行中任务的实时状态，而不是一张可以再次提交的空白表单，从根上杜绝误重复启动；对于仍愿意留在对话框里等待的用户，原有体验不受影响。其余以页面表单/按钮启动的长任务（启动挖掘、检索扩充、回灌、名单导入、备份/恢复/导出、数据目录迁移、重试发送）本就不弹出模态框，但也必须获得同样的"离开页面不中断、进度在任务中心可见、同型任务防误重复"待遇。

**Why this priority**: 它把"不影响用户使用其它功能"从挖掘一类任务扩展到全部长任务入口，是使用面最广的一步；依赖 US1 的进度承载能力（任务中心），故排在 P1 之后。

**Independent Test**: 对每个对话框动作（AI 扩充、种子翻译、内容起草、主题级多语言）各启动一次任务，运行中关闭对话框，核对任务继续执行、任务中心可见进度、完成后通知到达且结果可在相应位置查看；运行中重开对话框核对呈现进行中状态而非空白表单，重复启动数为 0。另对页面级入口抽查（如回灌、名单导入）：启动后离开页面核对任务继续且任务中心可见。

**Acceptance Scenarios**:

1. **Given** 用户从对话框启动了一次 AI 种子扩充，**When** 用户关闭对话框，**Then** 任务继续执行，任务中心可见其进度，全程无中断提示。
2. **Given** 该扩充任务仍在进行，**When** 用户重新打开扩充对话框，**Then** 对话框直接呈现该进行中任务的实时状态（阶段/进度），不提供可再次提交的初始表单。
3. **Given** 转入后台的备份任务完成，**When** 任意页面，**Then** 收到完成通知，点击可到达备份记录位置；任务中心可见其结果摘要。
4. **Given** 用户选择留在对话框内等待任务完成，**When** 任务结束，**Then** 原有体验保留：进度与结果汇总照常在对话框内呈现。
5. **Given** 用户从「导入与回灌」页启动了一次回灌任务，**When** 用户离开该页面，**Then** 任务继续执行，任务中心可见其进度与终态。

### User Story 3 - 终态提醒：离开页面也不错过结果 (Priority: P3)

用户把任务转入后台后去做别的事，任务完成或失败时不应该要求用户自己回来逐个翻查。系统需要在任务到达终态（完成/失败）时，无论用户当前在哪个页面，都给出一次不阻塞操作的应用内通知，包含任务名称与结果摘要（产出统计或失败原因），点击通知即可跳转到结果查看位置。用户主动发起的取消不产生通知。

**Why this priority**: 它是"离开页面"体验的收尾——从"随时可查"升级为"结果主动找我"；单点能力、独立可测，但价值依赖 US1/US2 先让任务能安心转入后台。

**Independent Test**: 在任意页面等待一个后台任务完成与一个任务失败，核对两种终态各出现一次通知、内容含摘要、点击可跳转；主动取消任务核对无通知；同一任务核对通知不重复出现。

**Acceptance Scenarios**:

1. **Given** 用户在"种子列表"页面停留，**When** 后台的挖掘任务完成，**Then** 出现含结果摘要（如新增联系方式数）的应用内通知，且不打断当前操作。
2. **Given** 一个后台任务失败，**When** 用户位于任意页面，**Then** 出现含失败原因的通知，点击可跳转到该任务相关页面。
3. **Given** 用户主动取消了某任务，**When** 取消生效，**Then** 不产生终态通知（用户已知晓该动作）。
4. **Given** 某任务已完成并通知过一次，**When** 用户切换页面或刷新，**Then** 该任务的终态通知不再重复出现。

---

### User Story 4 - 中断对账：重启后状态真实、可续跑 (Priority: P4)

应用退出会中止进程内的任务。当前被中止的任务在数据里永远停留在"运行中"，重新打开应用后任务列表里挂着永远不会动的"僵尸任务"，用户无法分辨哪些真的在跑。用户需要：应用启动时对账全部未结束任务，把已中止的标记为明确的"已中断"状态（区别于失败与取消），并提供可操作的后续——具备断点语义的任务（挖掘、回灌、导入等）可从入口重新运行且不重复已完成的工作；不具备安全重跑语义的任务（如发送进行中）给出明确的检查指引。此外，挖掘任务的明细记录状态须与任务台账保持一致，不出现台账已失败而明细停留"排队"的矛盾。

**Why this priority**: 它是任务中心可信度的地基（"显示运行中"必须真的在跑），但触发场景（任务运行中退出应用）相比日常使用频率低，且独立于 US1~US3 可单独交付。

**Independent Test**: 在挖掘任务运行中退出应用并重启，核对任务状态为"已中断"而非"运行中"、并提供重新运行入口；重新运行后核对不重复抓取已完成目标；构造任务失败场景核对其挖掘明细行状态与任务台账一致。

**Acceptance Scenarios**:

1. **Given** 挖掘任务运行中用户退出了应用，**When** 用户重新打开应用，**Then** 该任务显示为"已中断"，任务中心中显示"运行中"的遗留任务数量为 0。
2. **Given** 一个"已中断"的挖掘任务，**When** 用户从该任务入口重新运行，**Then** 任务从断点继续（已完成的目标不重复抓取），进度与统计延续累积。
3. **Given** 一个因错误而失败的任务，**When** 用户查看其挖掘明细，**Then** 明细状态与任务台账一致（失败/取消不再停留"排队"）。
4. **Given** 应用刚重启完成对账，**When** 用户查看任务中心，**Then** 所有显示"运行中"的任务均真实在执行（无幽灵任务）。

---

### Edge Cases

- **退出瞬间任务恰逢完成**：对账仅针对未结束任务；已写入终态的任务不得被误标"已中断"。
- **服务不可用**：沿用顶栏既有服务健康提示；任务中心以不可用态呈现，不得把过期数据显示为实时。
- **同一任务在详情页与抽屉同时可见**：两处状态必须一致；控制操作以服务端状态为准（重复点击暂停/恢复幂等）。
- **多个任务并行**：徽标显示运行中总数，抽屉分条展示，单任务操作不影响其它任务。
- **进度长时间无更新**（如单站限速等待、大模型响应慢）：已耗时继续累计，界面按最后阶段文案呈现，不误示为卡死。
- **通知目标位置缺失**：某任务类型无明确结果页映射时，跳转到任务中心并定位该任务。
- **已中断任务重跑与同类任务运行中并存**：启动入口明确提示已有进行中任务并给出查看入口，避免误重复启动。
- **运行中重开对话框恰逢任务刚结束**：呈现终态结果汇总（而非空白表单或"进行中"），不产生重复启动。

## Requirements *(mandatory)*

### Functional Requirements

**A. 全局任务中心（用户故事 1）**

- **FR-001**: 应用顶栏 MUST 常驻任务中心入口，并显示运行中任务数量徽标；该入口 MUST 在任意页面可见可用（数量为 0 时入口仍可打开，呈现最近任务或空态）。
- **FR-002**: 任务抽屉 MUST 列出全部未结束任务（排队中/运行中/已暂停），每条含：任务名称、类型、状态、进度（百分比或阶段化文案）、当前阶段说明、已耗时与起止时间。
- **FR-003**: 每条活跃任务 MUST 提供与该任务类型能力匹配的控制操作：取消（全部类型）、暂停/恢复（该类型支持时）；操作结果 MUST 与页内监控口径一致（同一状态机）。
- **FR-004**: 从抽屉 MUST 能一键跳转至该任务相关的详情/结果位置（如挖掘→挖掘任务页、群发→计划监控页、扩充/翻译/回灌→待审核等）。
- **FR-005**: 抽屉 MUST 同时呈现最近到达终态的任务（完成/失败/取消/已中断），供用户离开期间回看结果摘要；展示数量 MUST 有界（默认窗口：最近 24 小时且最多 20 条）。
- **FR-006**: 用户刷新页面或重新进入应用后，任务中心 MUST 自动恢复展示仍在执行的任务及其实时进度与状态，无需用户任何手动找回操作（不得要求用户手动点开某条记录开始监控）。
- **FR-007**: 进度事件连接中断时 MUST 自动重连，并以服务端最新快照补齐；恢复后进度与状态不得缺失或回退。
- **FR-008**: 同一任务在任务中心与页内监控视图的展示 MUST 同源一致，状态与进度不得出现矛盾。

**B. 对话框任务转入后台（用户故事 2）**

- **FR-009**: 全部以模态对话框启动长任务的入口（AI 种子扩充、种子翻译、内容起草、主题级多语言生成）MUST 支持"转入后台"：用户可关闭对话框（含 ESC/点击遮罩路径），任务继续执行，关闭前 MUST 有"关闭不会中断任务"的明确提示。
- **FR-010**: 转入后台的任务，其进度与终态 MUST 完整呈现在任务中心；到达终态时按 C 组（US3）口径通知。以页面表单/按钮启动的长任务（启动挖掘、检索扩充、回灌、名单导入、备份/恢复/导出、数据目录迁移、重试发送）同样 MUST 在启动后不因离开页面而中断，进度与终态 MUST 进入任务中心。
- **FR-011**: 任务进行期间重开同一对话框时，MUST 呈现该进行中任务的实时状态（而非可再次提交的初始表单）；同一入口 MUST NOT 因重开、重复提交或误操作产生重复任务；其它页面的同类启动入口在存在进行中同类任务时 MUST 明确提示并提供查看入口。
- **FR-012**: 关闭对话框（转入后台）MUST NOT 中断任务、MUST NOT 丢失已提交的参数与结果汇总；任务完成后结果仍可在任务中心与相应列表查看。
- **FR-013**: 选择留在对话框内等待完成的用户 MUST 保留既有体验（进度与结果汇总照常呈现）；后台化为可选路径，不强制改变操作习惯。

**C. 终态提醒（用户故事 3）**

- **FR-014**: 任务到达终态（完成/失败）时，无论用户当前位于哪个页面，MUST 给出应用内通知，内容含任务名称与结果摘要（成功产出统计或失败原因）。
- **FR-015**: 通知 MUST 可点击跳转至该任务相关的结果/详情位置，且 MUST NOT 阻塞用户当前操作。
- **FR-016**: 同一任务的终态通知 MUST 只出现一次；用户主动发起的取消 MUST NOT 产生通知。

**D. 中断对账与状态真实（用户故事 4）**

- **FR-017**: 应用启动时 MUST 对账全部未结束任务：进程内已无执行者的任务 MUST 被标记为"已中断"（独立状态，区别于失败与取消），MUST NOT 长期停留"运行中"。
- **FR-018**: "已中断"任务 MUST 提供可操作后续：具备断点语义的类型（挖掘、回灌、导入等）MUST 提供重新运行入口，重新运行 MUST NOT 重复已完成的工作（沿用断点续跑口径）；不具备安全重跑语义的类型（如发送进行中）MUST 给出明确的检查指引，不得直接一键重跑。
- **FR-019**: 挖掘任务明细记录的状态 MUST 与任务台账一致（运行中/完成/失败/取消同步更新），MUST NOT 出现台账已失败/取消而明细停留"排队"的不一致。
- **FR-020**: 任务中心显示"运行中"的任务 MUST 100% 对应真实执行中的任务；启动对账完成后，该口径在任意时刻成立（无幽灵任务）。

### Key Entities *(include if feature involves data)*

- **任务台账条目（沿用既有实体）**：类型、名称、状态（排队/运行/暂停/完成/失败/取消，新增"已中断"）、进度、结果摘要、错误信息、起止时间、关联对象引用（如挖掘明细、计划、备份记录）。"已中断"状态与对账行为支撑 FR-017~FR-020。
- **任务类型目录**：每种任务类型的展示名、是否支持暂停/恢复、是否具备安全重跑语义、对应的详情/结果页面（跳转目标）。支撑 FR-003、FR-004、FR-018。
- **任务中心视图状态**：活跃任务集合、最近终态集合、已通知标记（保证 FR-016 的不重复）。前端展示状态，非持久业务实体。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 从任意页面启动任一长任务后，用户在其它任意页面 ≤ 5 秒内可见其运行状态（徽标计数与抽屉进度），全程无需手动点击"监控"类操作。
- **SC-002**: 刷新页面或重新进入应用后，仍在执行任务的进度展示自动恢复，用户手动操作步骤为 0 次。
- **SC-003**: 全部对话框动作（4 个：AI 扩充、种子翻译、内容起草、主题级多语言）实测：关闭对话框后任务 100% 继续执行至完成，任务中心 100% 可见进度，完成结果 100% 可查；页面级长任务入口抽查（回灌、名单导入、备份）：离开页面后任务 100% 继续执行且任务中心可见终态。
- **SC-004**: 任务进行期间重开同一对话框，100% 呈现进行中状态而非空白表单；由此产生的重复任务数为 0。
- **SC-005**: 应用在任务运行中退出并重启后，显示"运行中"的遗留任务数量为 0（全部呈现为"已中断"），且 100% 提供后续操作入口。
- **SC-006**: 挖掘任务中断后经入口重新运行，重复抓取记录为 0（复验既有断点续跑口径）。
- **SC-007**: 终态通知在任意页面 100% 可见，同一任务重复通知次数为 0，点击后 ≤ 1 次操作到达结果查看位置。
- **SC-008**: 随机时刻抽查任务中心：显示"运行中"的任务全部真实在执行（幽灵任务 0 个，复验 FR-020）。

## Assumptions

- **执行边界**：任务仅在本地服务进程内执行，应用退出即中断（已与用户确认不要求跨退出继续执行）；中断后目标状态为"状态真实 + 可手动重跑"。
- **通知形态**：本期仅应用内通知（已与用户确认），不含系统级桌面通知。
- **不自动重放对外调用**：检索、大模型、发送等对外调用不因中断/重跑自动发起；"已中断"任务的重新运行一律由用户主动触发（沿用"对外调用由用户主动触发且可见可控"的既有原则）。
- **量级假设**：单用户桌面场景，同时活跃任务通常 ≤ 3 条；任务抽屉采用有界展示，无需分页与复杂筛选。
- **最近终态窗口**：默认"最近 24 小时且最多 20 条"，实现阶段可微调，不构成契约。
- **控制能力沿用**：暂停/恢复的支持范围以各任务类型既有能力为准（长时间、多阶段任务支持，短任务可能仅支持取消），任务中心只暴露该类型真实支持的操作，不新增控制语义。
- **基础设施复用**：沿用既有任务台账、进度事件与页内监控能力（001 已交付）；本特性不引入新的常驻调度、定时任务或跨进程守护。
- **页内监控保留**：挖掘任务页、计划监控页的页内视图保留，作为任务的详情视图；任务中心是全局入口与聚合视图，两者同源（FR-008）。
- **升级迁移**：升级后首次启动时，历史遗留的非终态任务同样按对账规则处理（标记"已中断"）。
