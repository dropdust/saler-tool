```bash
# 开发形态（后端 + 前端 dev）
cd backend && uv run uvicorn saler.api.dev:app --reload --port 8620

# 验收形态（构建产物 + 无窗服务 + headless Chrome CDP，沿用本机验收配方）
cd frontend && pnpm build

cd backend && uv run pytest tests/unit/test_prompt_registry.py tests/unit/test_seed_ai.py \
    tests/contract/test_ai_prompts_api.py
cd frontend && pnpm test && pnpm lint                     # prompt-editor-dialog + 两对话框入口 + 全量
```

> **前提声明**：V1–V3 的真实运行需要已配置的大模型服务（设置 → 大模型）；不可达时以假 Provider/离线样本走自动化层验证。V3 的 AI 辅助属真实外发调用（用户主动触发、入调用明细）。

## 2. 验证场景

### V1 自定义扩充提示词端到端（US1 / FR-001~008、014/015 / SC-001~004；模板库版 2026-10-16 修订）

前置：已配置大模型服务；种子库/图谱有若干节点。步骤：① 打开「AI 扩充」对话框，核对「提示词」入口与「默认」徽标；② 打开编辑器——核对默认模板全文、模板选择器（当前=「内置默认」）、变量面板（业务描述/已有节点/候选数量，含"将被替换为…"说明）、`{output_contract}` 槽位处的固定块只读呈现、长度额度（0/8000 起算）；③ 在模板中加入可辨认指令（如"候选机构必须包含行业展会与行业协会类别"）→「另存为」命名"东非市场"（创建即生效，≤3 次操作）；④ 核对徽标与选择器显示「东非市场」、编辑器内容回显；⑤ 发起一次扩充（填写描述、选节点、数量），完成后「查看调用明细」：核对 user 消息 = 所存模板内容且 `{description}`/`{existing_nodes}`/`{count}` 已替换为本次表单值、`{output_contract}` 处为固定结构段原文、系统消息仍为 JSON 守门；核对产出进入待审核且体现新增指令；⑥ 再「另存为」"展会渠道"（内容再作区分）→ 在选择器切回「东非市场」（选择即生效）→ 核实徽标同步 → 发起第二次扩充核对明细用东非版；⑦ 重命名"东非市场"→"东非-电力"核对生效；⑧ 删除"东非-电力"（二次确认）→ 核对自动回退「默认」且"展会渠道"仍在库中；⑨ 选择「内置默认」（=切回默认，已存模板保留）→ 再发起一次扩充核对明细用默认模板。预期：SC-001/003/004 达成；页内提示语言（"发送至已配置的大模型服务"）与实际一致。

**边界抽查（FR-005/015 阻断与警告）**：模板写 `{descriptoin}`（拼错）→ 保存后响应/提示列出 `unknown_variable`；删除 `{description}` 引用 → `missing_variable`；删除 `{output_contract}` → `missing_output_contract` 且运行明细末尾自动补结构段；清空模板 → 400"提示词不能为空"；粘贴 8001 字符 → 400 且提示额度；同名另存为 → 400 重名提示；「默认」态直接保存 → 引导另存为（命名后创建并生效，不覆盖默认）；运行中切换/删除模板 → 在途运行明细不受影响。

**验收结论（T301，2026-10-16）**：✅ 通过（headless Chrome CDP 真实点击流 + 本机 Mock Provider 真实 HTTP 调用）。方式：构建产物 + `--server` + 临时数据目录 `/tmp/saler-accept-006` + headless Chrome（脚本 `/tmp/saler-accept-006/v1-drive.mjs`，报告 `v1-report.json`，截图 18 张（含在途明细 1 张））；Provider 为 OpenAI 兼容本机 Mock（`/tmp/mock_llm.py`，逐请求落 JSONL 备查），明细核对以 provider 收到的真实请求为准并经 `llm_call` 落库交叉核验。**55 项断言全过**：①「默认」徽标与提示词入口在位；②默认模板全文（311 字符）回显、选择器=「内置默认（不可修改）」、四变量+槽位面板（含渲染说明与固定段只读块）、计数 `311/8000`；③加可辨认指令（"候选机构必须包含行业展会与行业协会类别"）另存为「东非市场」创建即生效；④徽标/选择器同步、内容回显；⑤扩充运行明细：user=所存模板原文且 `{description}`→「业务描述：…」、`{existing_nodes}`→「已有产品线：…/已有市场/国家：…」、`{count}`→20、`{output_contract}` 处为固定段原文、system 仍为 JSON 守门；出参体现新增指令（「Mock 行业展会协会」节点与「电力金具 展会 内罗毕」种子以 `pending` 落库）；⑥「展会渠道」另存为→切回「东非市场」即生效→二次运行明细用东非版；⑦重命名「东非-电力」生效；⑧删除生效模板自动回退「默认」且「展会渠道」仍在库；⑨切「内置默认」→ 三次运行明细用默认模板。边界：空模板客户端阻断（服务端 400 由契约测试锁定）、8001 字符计数变红且保存被阻断（不发请求、不走另存为引导）、`unknown_variable`+`missing_variable`+`missing_output_contract` 三警告齐现且「仍要保存」可成功、同名另存 400「模板名称已存在」、默认态保存引导命名（另存为新模板）、脏关闭确认。**运行中切换/删除（真实运行，provider 注入 4s 延迟拉开在途窗口）**：在途切换生效模板 → 该次运行明细仍为开始快照（含「在途专用标记句」），下一次运行用新模板；在途删除生效模板 → 在途不受影响、删除自动回退默认、下一次运行用默认模板（截图 `v1-17-inflight-drawer.png`；任务 12~15 全 completed）。**发现并修复 1 处缺陷**：默认态模板选择器实际显示灰色「请选择」而非「内置默认（不可修改）」（el-select 将空值视为未选择）——以 placeholder 承担呈现并补单测锁定（红→绿）；顺带消除 `AiContentDialog.vue` 2 条既有 lint 告警（T289 遗留）。

### V2 自定义起草提示词（US2 / FR-001~003、007、014）

前置：内容主题 1 个（已有或新建）。步骤：① 打开「AI 内容辅助」→「起草/润色母版」页签，核对「提示词」入口徽标；② 编辑器核对默认模板、模板选择器、变量面板（业务要点/语气/内容类型/语言）；③ 加入可辨认写作约束（如"正文首段必须以一句话概括价值主张"）另存为具名模板并生效；④ 发起起草（要点+语气）→ 明细核对 user 消息为该模板、`{brief}`→"业务要点：…"、`{tone}` 有值/缺省两态渲染语义正确、`{{company_name}}`/`{{signature}}` 未被误替换；⑤ 核对扩充模板库与生效选择不受影响（两功能独立）；⑥ 切回默认核对还原且起草模板保留。

**验收结论（T290，2026-10-16）**：✅ 通过（headless Chrome CDP 真实点击流 + 本机 Mock Provider；脚本 `v2-drive.mjs`，报告 `v2-report.json`，截图 10 张）。**35 项断言全过**：①内容对话框徽标「默认」在位（主题行需展开，入口在展开区）；②默认起草模板全文回显（含 `{{company_name}}`/`{{signature}}` 占位行）、`{tone}` 两态渲染说明、五枚变量/槽位、固定段只读；③加"写作约束：正文首段必须以一句话概括价值主张。"另存为「东非开发信模板」创建即生效；④运行 A（语气有值="直接、专业"）明细：user=该模板原文+「业务要点：…」+「语气：直接、专业。」+「撰写一条email（语言：zh）文案」+ `{{company_name}}`/`{{signature}}` 原样保留+JSON 守门，出参为 `{subject, body_md}` 草稿形状；运行 B（语气留空）「语气：专业、克制、以价值为先。」缺省两态落实（任务 9/10，`llm_call` 落行交叉核验）；结果流向：`content_variant` zh/`draft`/`llm_assisted` + 逐次新版本（`change_note`="AI 起草/润色"）；⑤两功能独立：扩充生效仍为默认、库仍 1 项（展会渠道）、扩充对话框徽标仍「默认」；⑥切回默认后编辑器还原默认全文、起草模板保留在库（枚举核对）；该次默认运行（任务 11）即 V4 起草侧证据。注：起草对话框内无「调用明细」内嵌入口，明细经任务中心任务卡「调用明细」核对（与 V1 的对话框内入口并存，属既有形态差异）。

### V3 AI 辅助编写（US3 / FR-009~012 / SC-005/006）

前置：已配置大模型服务。步骤：① 编辑器内输入意图（"面向东非市场，重点发掘各国电力公司与 EPC 总包"）→「AI 生成」→ 核对 ≤60s（常规 ≤30s）出现建议全文与 notes、请求期间编辑器可继续编辑；② 核对编辑器原文与已保存模板均未变；③「采用」→ 建议进入编辑器（dirty）→ 关闭不保存 → 重开核对已保存模板未变（采用≠保存）；④「丢弃」核对编辑器原内容不变；⑤ 对已写草稿「AI 优化」核对建议对照呈现；⑥ 编辑器内「查看调用明细」按 `operation=prompt_assist` 核对本次辅助的完整入参与 `{suggestion, notes}` 出参、用量；⑦ 断开/清空模型配置再试 → 409 提示与「设置 → 大模型」指引，编辑器内容无损。

**降级路径自动化**：`tests/contract/test_ai_prompts_api.py` 以 FakeLLMProvider 离线断言 ①②③⑤⑥⑦ 的服务端行为与 llm_call 落行。

**验收结论（T293，2026-10-16）**：✅ 通过（headless Chrome CDP + 本机 Mock Provider 真实调用；脚本 `v3-drive.mjs`，报告 `v3-report.json`，截图 9 张）。**23 项断言全过**：①输入意图「面向东非市场，重点发掘各国电力公司与 EPC 总包」→「AI 生成」：以 provider 注入 3.5s 延迟拉开请求窗——请求期按钮 loading 态为真、编辑器可继续编辑（请求期追加文本完整保留）、建议全文与 notes 出现；往返实测 3.6s（含注入延迟），远低于 60s 上限（≤30s 常规口径）；②编辑器原文与已保存模板均未变（API 详情前后一致、active 仍默认）；③「采用」写入编辑器并与建议 `<pre>` 原文逐一相等、提示「保存后才会对后续运行生效」；脏关闭放弃→重开=已保存模板（采用≠保存）；④「丢弃」建议区消失、编辑器原内容不变；⑤「AI 优化当前草稿」建议对照呈现、编辑器不动；⑥编辑器内「查看调用明细」= operation `prompt_assist`：生成入参（意图+变量目录+固定段原文）与优化入参（润色指令）齐备、出参 `{suggestion, notes}`、用量 100+50=150 tokens；⑦删除模型配置再试 → 409「尚未配置大模型服务：请前往「设置 → 大模型」添加并测试后再试」且编辑器内容无损（验后已还原 MockLLM）。说明：本机以外网不可达为前提，Mock 承载真实 HTTP 调用（响应形状与真实一致）；真实外网延迟未在本环境测量。
