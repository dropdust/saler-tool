# Feature Specification: 种子列表语言筛选

**Feature Branch**: `003-seed-language-filter`

**Created**: 2026-10-11

**Status**: Draft

**Input**: 用户描述："种子列表中添加语言筛选功能"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 按语言筛选种子列表 (Priority: P1)

销售人员运营多个语区的市场：种子库里同时存在英语、中文、俄语、阿拉伯语、西班牙语等语言的搜索词（种子创建时即带语言分类维度）。当需要针对特定语区的种子工作时（例如检查俄语种子质量、准备阿拉伯语执行批次），用户希望能在种子列表中按语言收窄视图：选择一个语言后，列表只呈现该语言的种子，结果总数与分页同步反映筛选结果；清除语言条件后恢复完整列表。语言条件必须能与其他筛选条件（搜索词、执行状态、审核状态、来源、批次，以及从其他页面带入的市场条件）自由组合，组合结果为各条件的交集。

**Why this priority**: 这是功能的最小可用切片——没有"可按语言收窄列表"，后续一切多语种工作流都无从谈起。种子语言是多语种营销的第一检索维度：营销内容与发送语言都按客户语言匹配，种子语言错配会直接导致产出线索的语言错配。

**Independent Test**: 在含多语言种子的列表中，选择任一语言并查询，核对列表内仅含该语言的种子、总数与分页正确；清除后恢复完整列表；与其他筛选条件叠加时核对交集结果。

**Acceptance Scenarios**:

1. **Given** 种子库包含英语、俄语、阿拉伯语等多种语言的种子，**When** 用户在种子列表选择语言"俄语"并查询，**Then** 列表仅显示俄语种子，总数与分页与该结果一致。
2. **Given** 用户已按"俄语"筛选且页面上同时设置了其他筛选条件（如审核=已采纳），**When** 用户清除语言条件并查询，**Then** 列表恢复为未按语言过滤的结果，且其他筛选条件的取值保持不变。
3. **Given** 用户设置了搜索词、执行状态、来源、批次等条件，**When** 用户追加语言条件并查询，**Then** 结果中的每条种子同时满足语言条件与全部既有条件（交集），无任何违反条件的记录混入。
4. **Given** 库中尚不存在某语言的种子，**When** 用户选择该语言并查询，**Then** 显示明确的空结果状态，不显示其他语言的种子、不报错。

### User Story 2 - 语言筛选融入既有运营工作流 (Priority: P2)

语言筛选的价值在既有工作流中兑现：① **翻译复核**——用户用"翻译选中"把中文种子翻译成俄语、阿拉伯语等目标语言后，产出进入"待审核"区，用户需要按"语言=目标语言 + 审核=待审核"筛出刚产出的候选并逐条复核；② **执行准备**——用户按"语言=阿拉伯语 + 执行状态=待执行 + 审核=已采纳"筛出可直接核对/导出的执行清单，清单内语言零混杂；③ **结果内操作**——在语言筛选后的结果上继续使用列表既有操作（勾选、翻译选中、编辑、失效），操作对象与可见范围一致，操作完成后列表保持在语言筛选条件下刷新为正确结果。

**Why this priority**: 这是从"筛选可用"到"筛选有用"的跨越：翻译与执行是本工具最高频的两个种子操作，语言筛选正是这两条链路上的关键枢纽。它建立在 US1 之上，但可用端到端场景独立验收。

**Independent Test**: 执行一次"翻译选中"把一批中文种子翻译为俄语，随后用"语言=俄语 + 审核=待审核"筛出全部产出并逐条采纳；再以"语言=阿拉伯语 + 执行状态=待执行"得到执行清单并与实际种子数量核对。

**Acceptance Scenarios**:

1. **Given** 用户刚完成一批中文种子→俄语的翻译且产出均为待审核，**When** 用户按"语言=俄语、审核=待审核"筛选，**Then** 全部（且仅）该批产出出现在结果中，条数与实际翻译产出数一致。
2. **Given** 用户要为阿拉伯语市场准备执行清单，**When** 按"语言=阿拉伯语 + 执行状态=待执行 + 审核=已采纳"筛选，**Then** 结果可直接作为执行清单使用，清单内不含其他语言的种子。
3. **Given** 用户已按某语言筛选且结果中存在可操作种子，**When** 用户在结果内执行"翻译选中/编辑/失效"等既有操作，**Then** 操作仅作用于所选种子，操作完成后列表在保持语言筛选条件下刷新且结果正确。

### User Story 3 - 筛选选项对库内语言全覆盖（可见即可筛） (Priority: P3)

种子可通过批量导入与外部回灌进入库（表格式的既有种子清单、收割回灌结果等），其中的语言取值可能使用应用标准语言表之外的代码，或存在大小写、空白等写法差异。语言筛选必须"可见即可筛"：任何在列表中出现过的语言取值，都能在筛选选项中选到并筛出对应种子；标准语言显示统一中文标签，非标准代码原样显示——不得让任何语言的种子成为筛选死角。

**Why this priority**: 覆盖完整性是"放心用"的质量门槛。用户迁移既有种子清单（如旧项目的历史数据）后，若发现某些种子按语言筛不出来，会对整个筛选功能失去信任，而这类迁移数据正是本工具的首批导入样例。它不影响 US1/US2 的基本可用性，但必须作为覆盖审计项独立验收。

**Independent Test**: 导入若干携带非标准语言代码（如 "ko"）与写法差异（如 "EN"）的种子，打开语言筛选确认这些取值可选、可筛出对应且仅对应的种子。

**Acceptance Scenarios**:

1. **Given** 种子库经导入/回灌引入了标准语言表之外的代码（如 "ko"），**When** 用户打开语言筛选，**Then** 该代码出现在选项中并原样显示，选择后筛出全部该代码的种子。
2. **Given** 库中同一语言存在写法差异（如 "en" 与 "EN" 并存），**When** 用户分别筛选这两种写法，**Then** 各自筛出对应种子，互不混淆、互不漏筛。
3. **Given** 某语言取值已在种子列表中出现（如 "ko"），**When** 用户打开语言筛选的选项列表比对，**Then** 该取值必然存在可选中并筛出对应种子的选项（可见即可筛，无死角）。

---

### Edge Cases

- **筛选结果为空**：显示明确空态（区别于加载失败的提示）；不得回退显示未过滤数据、不得报错。
- **页码越界**：用户在结果后页时应用更严格的筛选（如某语言种子不足一页），界面必须呈现有效内容（自动回到有效页或明确空态），不得出现空白列表假象或卡死。
- **非标准语言代码**：导入/回灌带入的代码在选项中原样显示且可选、可筛（见 US3）。
- **大小写与空白差异**：不得因写法差异导致漏筛（"可见即可筛"）。
- **组合条件冲突**：语言与既有条件组合后无结果时，空态呈现，且各条件当前取值清晰可辨，用户可单独清除语言条件以验证。
- **未选择语言**：等同"不施加语言限制"（显示全部语言），无需额外选择"全部"；清除语言条件一步完成。
- **数据零变更**：筛选是纯查询行为，反复应用/清除不改变任何种子数据与状态。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 种子列表 MUST 提供按语言筛选的控件；筛选选项 MUST 覆盖 ① 应用统一语言表中的全部语言（显示统一中文标签，如"俄语（ru）"）与 ② 种子库中实际出现的其他语言取值（原样显示代码）。
- **FR-002**: 用户选定某语言后，列表 MUST 仅呈现该语言的种子；未选择语言时 MUST 不施加语言限制（呈现全部语言的种子）。
- **FR-003**: 语言条件 MUST 与全部既有筛选条件（搜索词、执行状态、审核状态、来源、批次及从其他页面带入的市场等条件）以交集方式组合生效；结果总数与分页 MUST 与组合条件一致。
- **FR-004**: 用户 MUST 能一步清除语言条件，恢复未按语言过滤的结果；清除语言条件 MUST NOT 影响其他筛选条件的当前取值。
- **FR-005**: 筛选控件 MUST 明确呈现当前所选语言；未选择时 MUST 明确表现为"未按语言筛选"状态。
- **FR-006**: 任何在列表中可见的语言取值 MUST 在筛选项中可选且可筛出对应种子（含非标准代码与写法差异）；MUST NOT 出现"数据存在但无法按语言筛出"的漏筛。
- **FR-007**: 筛选结果为空时 MUST 显示明确的空态；MUST NOT 回退显示未过滤数据，MUST NOT 以错误状态呈现。
- **FR-008**: 应用或清除语言条件后，列表 MUST 呈现有效结果（自动回到有效页或明确空态），MUST NOT 因原页码越界出现空白列表。
- **FR-009**: 语言筛选 MUST 为纯查询行为：MUST NOT 修改种子数据或状态，MUST NOT 触发任何对外调用（大模型/检索/发送）。
- **FR-010**: 语言筛选下的列表 MUST 与既有列表能力兼容（排序、分页、勾选、翻译选中、编辑、失效）：操作对象与筛选结果范围一致，操作后列表在保持语言条件下刷新为正确结果。

### Key Entities *(include if feature involves data)*

- **种子（Seed）**：沿用既有实体；本特性使用其既有"语言"分类维度（每条种子恰有一个语言取值，创建默认英语）作为筛选维度，不新增字段、不改变取值规则。
- **语言选项集合**：筛选候选项 = 应用统一语言表 ∪ 种子库中实际出现的语言取值；标签规则：标准语言显示统一中文标签，其他取值原样显示代码。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户可用 1 步操作发起一次语言筛选；筛选后结果中非目标语言的种子条数为 0。
- **SC-002**: 语言条件与任意既有筛选条件组合时，结果条数与各条件交集的理论值核对一致率 100%（抽查不少于 5 组组合条件）。
- **SC-003**: 库中每种实际存在的语言取值（含非标准代码与写法差异）在筛选项中均有可选项且可筛出非空结果；"可见但筛不到"的语言取值数为 0。
- **SC-004**: 清除语言条件后，列表恢复为与筛选前一致的完整结果（条数一致、其他条件不变）。
- **SC-005**: 在 10,000 条种子规模下，应用或清除语言筛选后的列表呈现时间不超过 1 秒，与既有同类筛选操作相比无可见退化。
- **SC-006**: 翻译复核场景中，"语言 + 待审核"筛出的条数与实际翻译产出条数一致率 100%。
- **SC-007**: 引入语言筛选后，种子列表既有功能（筛选、排序、分页、勾选、翻译、编辑、失效）的回归缺陷数为 0。

## Assumptions

- **单值单选**：语言筛选为单值筛选，交互方式与页面现有筛选项（执行状态/审核/来源/批次）保持一致；"一次筛选多个语言（如俄语或阿拉伯语）"不在本期范围，如需要可作为后续增补。
- **选项完整性优先于精简**：选项始终覆盖应用统一语言表（含库中暂未有种子的语言，选择后呈现空态），以保证与建种、翻译等处使用的语言范围一致；数据中出现的其他取值另行补齐。
- **临时视图条件**：语言筛选是列表页的临时视图条件，不做跨页面记忆、不随页面跳转自动携带；本期不要求其他页面以携带语言条件的方式跳转到种子列表（既有市场深链等机制不受影响）。
- **范围边界**：导出执行清单、产量统计、待审核页等其他入口的语言条件不在本期范围；本期仅覆盖种子列表页的筛选控件。
- **数据规则不变**：沿用既有数据模型（每种子单语言、创建默认英语）；本特性不做历史数据规范化，也不追溯修改任何语言取值。
- **单用户单机**：应用为单用户本地桌面工具，语言筛选无需权限与并发控制。
