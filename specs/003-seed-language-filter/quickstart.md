## 2. 验证场景

### L1 按语言筛选与组合（US1 / FR-002~005 / SC-001/002/004）

前置：种子库含多语言种子（可用 001 S3/S4 数据，或批量导入构造：en / ru / ar / zh 各若干条，跨批次、跨状态与审核状态）。
步骤：① 在种子列表"语言"选择"俄语（ru）"→ 查询，逐行核对语言列；核对总数与分页；② 叠加执行状态/搜索词等条件 → 查询，核对交集数量；③ 清除语言条件 → 查询，核对恢复全量且其他条件不变；④ 观察控件对当前所选语言的呈现；未选择时的占位呈现。
预期：结果零语言混杂（SC-001）；条数 = 各条件交集（SC-002）；清除后条数与筛选前一致（SC-004）；控件当前态清晰可辨。

**验收结论（T185，2026-10-11）**：✅ 通过（CDP 自动驱动）。方式：构建产物 + `--server` 模式（临时数据目录）+ headless Chrome（CDP，1360×900；脚本 `/tmp/saler-accept-003/drive.mjs`）。数据：74 条种子（ru 60 + en 4 + zh 3 + ar 2 已采纳；ru-LLM 5 条待审核）。证据：初始 69 条（默认审核=已采纳）→ 语言=俄语 60 条零混杂（首屏 50 行逐行核对语言列）→ 叠加搜索词"вариант 59"交集 1 条 → 叠加审核=待审核交集 5 条 → 一步清除（真实点击 clear 图标，`请选择`恢复）查询恢复 69 条；控件当前态"俄语（ru）"清晰可辨；控制台 0 错误；截图 `L1-ru-filter / L1-ru-pending / L1-clear-restore.png`（/tmp/saler-accept-003/）。

### L2 翻译复核与执行准备（US2 / FR-003/010 / SC-006）

前置：已配置大模型（或跳过真实翻译，以批量创建模拟产出：`source=llm`、`lang=ru`、`review_status=pending`）。
步骤：① 对若干中文种子执行"翻译选中"→ 目标 ru（或模拟产出）；② 按"语言=ru + 审核=待审核"筛选：核对条数与产出数一致，逐条采纳；③ 按"语言=ru + 执行状态=待执行 + 审核=已采纳"筛选：得到执行清单，核对清单内无其他语言；④ 在筛选结果内勾选种子执行"编辑/失效/翻译选中"，观察操作后列表（保持语言条件）刷新结果。
预期：②条数一致率 100%（SC-006）；③清单零语言混杂；④操作仅作用于所选种子，列表刷新正确（FR-010）。

**验收结论（T187，2026-10-11）**：✅ 通过（CDP 自动驱动 + 真实审核流转）。方式：构建产物 + `--server` + headless Chrome（脚本 `/tmp/saler-accept-003/drive-l2.mjs`）。证据：模拟翻译产出 6 条待审核 ru（`source=llm`，与真实翻译流程产出同形状）→ "语言=ru + 审核=待审核 + 搜索词"筛出恰好该批产出（6 条与产出条数一致，SC-006）→ 经既有审核流转采纳后 "语言=ru + 审核=已采纳 + 执行状态=待执行" → 66 条（60 存量 + 6 新产出，全量核对）→ 叠加搜索词聚焦产出子集 6 条、零语言混杂（执行清单）→ 结果内"失效"操作后列表在保持语言条件下刷新（6→5，控件仍显示"俄语（ru）"）；截图 `L2-review-batch / L2-exec-list / L2-after-disable.png`；控制台 0 错误。注：真实大模型翻译为可选增强（产出形状与模拟一致），不影响本场景结论。

### L3 全覆盖与"可见即可筛"（US3 / FR-001/006 / SC-003）

步骤：① 以 csv 批量导入含非标准代码（如 `ko`）与大小写变体（如 `EN`）的种子；② 打开语言筛选：确认 17 个标准语言（中文标签）＋ `ko`、`EN`（原样代码）均在选项中；③ 分别选择 `ko`、`EN`、`en`：各自筛出对应且仅对应的种子。
预期：任何列表可见取值均有可选项且可筛出（SC-003 死角为 0）；`EN` 与 `en` 互不混淆、互不漏筛。

**验收结论（T190，2026-10-11）**：✅ 通过（CDP 自动驱动）。方式：构建产物 + `--server` + headless Chrome（脚本 `/tmp/saler-accept-003/drive-l3.mjs`）。数据：导入 2 条 `ko` + 3 条大写变体 `EN`（模拟 csv 批量导入既有清单）。证据：`/seeds/langs` 返回 `["EN","ar","en","ko","ru","zh"]`（原样、不折叠）→ 语言选项列表 19 项 = 17 标准 + `EN` + `ko`（`L3-options-raw.png` 可见标准标签，变体项经 DOM 断言确认原样）→ 分别筛选：`ko` → 2 条（语言列原样 `ko`）、`EN` → 3 条（原样 `EN`）、标准"英语（en）" → 4 条（既有小写种子，语言列"英语"）——三组互不混淆、互不漏筛，"可见但筛不到"为 0（SC-003）；控制台 0 错误。

### L4 空态与页码边界（FR-007/008）

步骤：① 选择库中无种子的语言（如波斯语 fa）→ 查询：观察空态文案（应为"没有符合当前筛选条件的种子"类明确文案，非笼统"暂无数据"、非报错、不显示其他语言数据）；② 翻到结果第 2 页 → 改选一个结果不足 1 页的语言 → 查询：观察页面呈现。
预期：①空态明确且不误导；②直接呈现第 1 页有效结果（或明确空态），无空白列表、分页状态正确。

**验收结论（T185，2026-10-11）**：✅ 通过。证据：① 语言=波斯语（fa，库内无种子）→ 0 条且空态文案"没有符合当前筛选条件的种子"（非笼统"暂无数据"、不显示其他语言数据，`L4-empty-state.png`）；② 俄语 60 条翻至第 2 页（10 条）后改选中文（3 条）→ 查询复位第 1 页、3 条有效结果不空白（`L4-page2 / L4-page-reset.png`）；两步均无控制台错误。

## 3. 常见问题排查

| 现象 | 排查方向 |
|---|---|
| 语言下拉中看不到某语言 | 检查 `GET /seeds/langs` 是否包含该值；检查选项组装是否过滤了非标准取值（应原样保留） |
| 选择语言后仍有其他语言混入 | 检查列表请求是否携带了 `lang` 参数；核对精确匹配语义（`EN` ≠ `en`） |
| 筛选后出现空白列表 | 确认查询动作已将页码复位为第 1 页；核对 `total` 与分页状态一致 |
| 选择"英语（en）"却筛不出 `EN` 的种子 | 精确匹配为既定语义：`EN` 是独立选项，请在选项中直接选 `EN` |
| 筛选动作疑似改动数据 | 检查网络面板是否有写请求（筛选必须为纯查询，FR-009） |
