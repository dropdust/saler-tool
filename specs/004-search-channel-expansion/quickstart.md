# Quickstart: 检索渠道扩展——密钥申请指引与免密钥搜索引擎

**Feature**: `004-search-channel-expansion` | **Date**: 2026-10-12

本文件是**验证指南**：如何运行本特性并按用户故事逐条验证。数据形状见 [data-model.md](data-model.md)；接口约定见 [contracts/search-channel-expansion-contract.md](contracts/search-channel-expansion-contract.md)；通用环境前提与打包流程沿用 [001 quickstart §1–§3](../001-sales-tool/quickstart.md)。

## 1. 运行与测试

```bash
# 开发形态（后端 + 前端 dev；壳形态：pnpm build 后 python -m saler.desktop）
cd backend && uv run uvicorn saler.api.main:app --reload --port 8620
cd frontend && pnpm dev                                   # http://localhost:5173

# 自动化测试（离线可跑，无真实外网依赖）
cd backend && uv run pytest tests/contract/test_search_providers.py tests/contract/test_search_presets.py tests/unit/test_search_stats.py
cd frontend && pnpm test && pnpm lint                     # search-providers / 既有全量
```

> **网络前提声明**：V2~V3 的真实查询需要用户网络可达目标服务（境外引擎在受限网络下需自备代理，沿用全局代理配置）。**共享/数据中心出口被风控是已知现实**（runte 量产教训），Google 等引擎真实测试失败属于预期呈现；"安全失败 + 自动切换 + 可诊断"由离线契约测试（V4/V5）保证，真实网络的单引擎成功不作为验收必要条件。

## 2. 验证场景

### V1 预置信息一屏直达（US2 / FR-013~016 / SC-005）

前置：无需密钥。步骤：① 打开「设置 → 检索渠道」→ 添加渠道 → 逐一选择 10 个类型，查看信息卡（接入方式标签、申请地址、note、market、risk）；② 点击 Brave/Serper/Tavily 的申请地址按钮；③ 打开一个已配置渠道的"编辑"，核对同样可见其类型信息卡。

预期：3 个需密钥类型 100% 有可点击申请地址（SC-005），点击一次即在**系统浏览器**打开官方页面；免密钥 7 类型显示"无需密钥"且**不出现密钥输入框**；申请地址旁有服务商名/域名可读（FR-016 兜底）。后端完整性由 `test_search_presets.py` 锁定。

**验收结论（实现阶段填写）**：

### V2 添加与测试免密钥渠道（US1 / FR-001~003 / SC-001）

前置：网络可达（或仅验证失败路径的呈现）。步骤：逐一添加 百度 / Google / Bing / Mojeek / DuckDuckGo / Wikipedia（全程不填密钥）→ 点"测试"，计时。

预期：添加完成 ≤1 分钟且无需离开应用查资料（SC-001）；成功 → 显示结果样例与"正常"；失败 → 呈现**类别化原因**（限流/风控封禁/网络/解析失败），渠道仍可保存与显示接入方式标签。

**验收结论（实现阶段填写）**：

### V3 真实查询、链接还原与来源记录（US1 / FR-003~005、FR-012 / SC-002/006）

前置：配置不止一个免密钥渠道；建一次小批量检索任务（如「资源/种子 → 检索扩充图谱」1~2 条查询，或线索挖掘任务）。步骤：① 运行任务；② 检查候选记录的来源（渠道 + 命中查询）；③ 抽检结果链接（≥20 条）核对是否**直接指向结果站点**（无 baidu.com/link、bing.com/ck、google /url 等包装）；④ 在网络可达前提下逐引擎单独测试，记录各引擎是否返回 ≥1 条结果。

预期：来源字段完整（口径与付费渠道一致）；链接还原率 ≥95%（SC-006）、无包装链接入库；6 引擎在可达前提下逐一跑通（SC-002；受限网络失败如实记录不判缺陷）。

**验收结论（实现阶段填写）**：

### V4 风控安全与空结果纪律（US1 / FR-007~009 / SC-003）

方式：**离线回放**——`test_search_providers.py` 以固化样本（各引擎验证页/伪装页/静默 captcha/结构改版页）断言：全部归类 `blocked`/`parse`、0 条数据写入、无一被当作结果或合法空。可选人工复核：百度连续无节制请求触发验证页后，观察渠道健康转"异常（风控封禁）"与任务自动切换。

预期：有害数据 0 条；样本 100% 可复现判失败；合法空结果样本（不触发失败）返回 `[]` 且任务继续。

**验收结论（实现阶段填写）**：

### V5 混合链故障转移与运行时记账（US1+US3 / FR-005/006/018 / SC-004）

步骤：① 配置混合链：其一为可稳定失败的渠道（如端点改为不可达主机的 Bing，或触发限流的样本服务）→ 运行一次任务；② 观察任务不中断、按序切换；③ 打开渠道列表：核对"今日用量"计数包含失败尝试、"健康=异常"且原因标签与失败类别一致 → 恢复渠道再成功一次 → 核对健康回到"正常"且失败原因清空。

预期：单渠道失败 0 中断（SC-004）；用量/健康/最近失败三者在测试与任务同口径、按契约 §3 状态机迁移。

**验收结论（实现阶段填写）**：

### V6 风险透明与指引一致性（US3 / FR-017~020 / SC-007）

步骤：① 渠道列表逐行核对"接入方式"标签（官方 API / 网页解析）全覆盖；② 制造网络类失败（端点改为不可达主机）→ "测试" → 失败提示应为**网络类**且不误示为密钥问题；③ 检查页面指引 alert 与 crawl 409 文案：不再出现"Bing 已退役…均不可用"类过时结论，免密钥渠道的"非官方接入、合规责任自担"提示可见。

预期：标签 100% 覆盖（SC-007）；失败分类正确（FR-018）；指引与本特性渠道集合一致（FR-019）；风险提示与既有 DDG 口径一致（FR-020）。
