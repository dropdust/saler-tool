# Feature Specification: 检索渠道扩展——密钥申请指引与免密钥搜索引擎

**Feature Branch**: `004-search-channel-expansion`

**Created**: 2026-10-12

**Status**: Draft

**Input**: 用户描述："添加检索渠道时，提供的几个服务商需要补充一下他们API密钥申请地址。另外，是否可以提供一下利用搜索引擎：百度、google、 DuckDuckGo、Mojeek、Bing 、Wikipedia 这些各国知名免费搜索服务爬取的方式。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 免密钥免费搜索引擎渠道，零成本可用 (Priority: P1)

用户面向多个国家市场获客：中文市场的客户资料要用百度检索中文网页；全球市场依赖 Google 与 Bing 的覆盖面；Mojeek 提供独立索引来源；DuckDuckGo 适用于注重隐私的场景；Wikipedia 用于机构资料的检索与佐证。这些服务商要么没有面向公众的免费官方搜索接口（Bing 搜索 API 已退役、Google PSE 已对新客户关闭），要么免费额度有限。用户希望**不申请任何密钥**，就能把这些知名免费搜索服务作为检索渠道加入工具：添加后完成连通测试，即可在种子发现、图谱扩展等任务中按优先级使用；单个引擎被限流或拦截时自动切换下一渠道，任务不中断，异常页面内容绝不写入线索数据。

**Why this priority**: 检索渠道是整个获客链路的数据源头；免密钥渠道既显著降低使用门槛（无需注册、绑卡、申请流程），又补齐多国市场覆盖（如百度之于中文市场、Mojeek 之于独立索引、Wikipedia 之于机构资料），是本次请求的核心价值切片。

**Independent Test**: 逐个添加六个免密钥渠道，各执行一次连通测试与真实查询，核对返回结构化结果（标题 + 可直接访问链接）；构造拦截/限流响应验证安全失败与自动切换；在混合渠道配置（付费 + 免费）下执行一次小批量检索，核对来源记录与既有口径一致。

**Acceptance Scenarios**:

1. **Given** 用户未配置任何密钥，**When** 用户在检索渠道页添加"百度"类型渠道并点击测试，**Then** 测试成功并返回真实结果样例，渠道出现在列表中（全程无需填写密钥）。
2. **Given** 已配置百度与 Google 两个免密钥渠道（百度优先级在前），**When** 百度返回人机校验/拦截页，**Then** 系统将百度按失败处理并自动切换 Google 完成任务，无任何来自拦截页的内容被记录。
3. **Given** 用户配置了免费渠道与付费渠道混合的链路，**When** 执行一次检索任务产生候选，**Then** 每条候选记录来源渠道与命中查询（免费渠道与付费渠道口径一致）。
4. **Given** 某引擎结果链接为跳转包装（如百度跳转链接、搜索引擎中转域），**When** 结果入库，**Then** 记录的链接为可直接访问的目标链接而非包装链接。

---

### User Story 2 - 服务商密钥申请地址与决策要点一屏直达 (Priority: P2)

用户在"添加渠道"时为 Brave、Serper.dev、Tavily 等需要密钥的服务商配置渠道。当前界面只有名称与一行备注，用户必须自行去搜索引擎查"哪里注册、哪里申请密钥、免费额度多少、有无条款风险"。用户希望在选择渠道类型时，界面直接给出该服务商的**官方密钥申请地址**（一键在系统浏览器打开）以及决策要点（免费额度、是否绑卡、条款限制、适用市场），在一个界面内完成"了解 → 申请 → 回到应用粘贴密钥"的闭环；编辑既有渠道（密钥续期/更换）时同样可见。

**Why this priority**: 申请地址是最常被问到却缺失的信息，补充成本小、见效直接；与免费渠道（P1）相互独立，可单独交付。

**Independent Test**: 打开添加渠道对话框，逐一选择各需密钥类型，核对申请地址链接可点击直达、决策要点完整；核对免密钥类型的"无需密钥"呈现；验证编辑既有渠道时同样可见。

**Acceptance Scenarios**:

1. **Given** 用户在添加渠道对话框选择"Brave Search"，**When** 查看表单，**Then** 呈现 Brave 官方密钥申请地址的可点击入口与免费额度/条款要点，点击即在系统浏览器打开对应页面。
2. **Given** 某预置类型的申请地址失效，**When** 用户查看该类型说明，**Then** 仍可见服务商名称与域名并可自行检索最新入口，配置流程不被阻断。
3. **Given** 用户编辑一个已配置的 Serper.dev 渠道（如密钥续期场景），**When** 打开编辑对话框，**Then** 同样可见该类型的申请地址与决策要点。

---

### User Story 3 - 免费渠道的运行时风险透明 (Priority: P3)

免费网页解析型渠道的可用性受服务商反爬策略影响（限流、人机校验、软封禁），与官方 API 渠道的稳定性存在本质差异。用户需要：渠道列表上一眼区分接入方式（官方 API / 网页解析型）；失败时能分辨原因（限流？风控封禁？网络不可达？页面改版？）以决定处置（换渠道、挂代理、调整优先级）；页面指引不再出现过时结论，并对免费渠道的性质与合规责任有清楚提示。

**Why this priority**: 预期管理与可诊断性决定这类渠道是否"好用"；没有风险透明，用户会把风控失败误判为产品缺陷或密钥问题。

**Independent Test**: 构造各类失败（限流/风控封禁/网络不可达/解析失败）核对界面呈现的原因区分；核对渠道列表接入方式标签；核对页面指引文案与当前支持的渠道集合一致。

**Acceptance Scenarios**:

1. **Given** 某免费渠道连续被限流，**When** 用户查看渠道列表，**Then** 该渠道健康状态与最近一次失败原因（限流类别）清晰可见。
2. **Given** 用户在受限网络（不可达某境外引擎），**When** 用户测试该渠道，**Then** 失败提示归为网络类并提示可检查代理配置，且不误示为密钥问题。
3. **Given** 用户查看渠道列表与页面指引，**Then** 每个渠道可见其接入方式标签（官方 API / 网页解析型），指引信息与当前支持的渠道集合一致、无过时结论。

---

### Edge Cases

- **人机校验/拦截页**（HTTP 成功但内容为验证页，如"百度安全验证"）：必须判定为失败并切换渠道，绝不解析写入数据。
- **软封禁伪装页**（返回诱饵内容冒充正常结果）：按失败识别处理（沿用既有 DuckDuckGo 兜底渠道的防脏数据口径）。
- **合法零结果 vs 拦截空页**：尽可能区分；无法区分时按失败处理（宁可误判失败，不得写入可疑数据）。
- **页面结构改版**：解析失败必须归类为失败并标记渠道异常，不崩溃、不静默返回空结果、不误报成功。
- **跳转包装链接无法还原**：无法确定目标链接的结果条目必须丢弃并计为解析异常，不得记录包装链接。
- **受限网络下境外引擎不可达**：按网络类失败处理并提示检查代理配置；不得误导为密钥问题。
- **全部渠道均不可用**：任务暂停并提示补充渠道，提示内容涵盖新增免费渠道的引导。
- **同一引擎配置多个实例**（如两个百度渠道用于不同用途）：允许，与既有多渠道模型一致。
- **自定义端点覆盖**（用户自建镜像/代理网关）：免费渠道同样保持端点可配置。
- **目标语言/语区不受引擎支持**：忽略该参数继续检索，不报错（如 Wikipedia 语言版本选择）。

## Requirements *(mandatory)*

### Functional Requirements

**A. 免密钥免费搜索引擎渠道（用户故事 1）**

- **FR-001**: 系统 MUST 提供六种免密钥检索渠道类型：百度、Google、DuckDuckGo、Mojeek、Bing、Wikipedia；其添加、命名、优先级设置、启停、连通测试与删除能力 MUST 与既有渠道完全一致。
- **FR-002**: 免密钥渠道 MUST 无需任何密钥即可完成连通测试与执行检索；相关表单 MUST NOT 要求填写密钥字段，并 MUST 明确标注"无需密钥"。
- **FR-003**: 免密钥渠道 MUST 将查询转换为结构化结果：每条含标题与可直接访问的目标链接；引擎页面提供摘要时 MUST 一并抽取摘要片段。
- **FR-004**: 结果链接若为跳转包装（搜索引擎中转域/跳转参数），MUST 还原为可直接访问的目标链接；MUST NOT 将包装链接作为结果或来源写入任何数据。
- **FR-005**: 免密钥渠道 MUST 参与与既有渠道相同的优先级调用与自动故障转移；单渠道失败 MUST 自动切换至下一可用渠道，MUST NOT 中断任务（转移链中存在可用渠道时）。
- **FR-006**: 六种渠道 MUST 与既有渠道一样计入健康状态（正常/异常）与当日用量统计。
- **FR-007**: 遇到人机校验页、拦截页、限流或软封禁（返回异常内容冒充正常页）时 MUST 判定为失败并按既有失败类别（限流/风控封禁等）归类；MUST NOT 将此类页面内容作为检索结果、空结果或其他数据写入。
- **FR-008**: 页面结构变化导致解析失败时 MUST 判定为失败并标记渠道异常；MUST NOT 崩溃、静默返回空结果或误报成功。
- **FR-009**: 合法"零结果"与"被拦截后无结果" MUST 尽可能区分；无法区分时 MUST 按失败处理。
- **FR-010**: 免密钥渠道 MUST 遵守既有礼貌抓取约束（请求间隔、并发上限），并支持既有代理配置。
- **FR-011**: 渠道配置 MUST 支持语言/语区参数（引擎支持时生效，如 Wikipedia 语言版本用于机构资料检索与佐证；百度默认面向中文）；引擎不支持时 MUST 忽略且不报错。
- **FR-012**: 通过免密钥渠道命中的候选 MUST 按既有口径记录来源渠道与命中查询。

**B. 服务商密钥申请与决策要点（用户故事 2）**

- **FR-013**: 每个需要密钥的预置渠道 MUST 提供其官方密钥申请/开通地址；用户可从渠道界面一键在系统浏览器打开该地址。
- **FR-014**: 每个预置渠道（含免密钥类型）MUST 统一呈现决策要点：是否需要密钥、申请地址（需要时）、免费额度/计费要点、适用市场与定位（如 百度—中文市场；Google/Bing—全球；Mojeek—独立索引；Wikipedia—机构资料与佐证）、已知条款与风险提示。
- **FR-015**: 编辑既有渠道时 MUST 同样可见该类型的申请地址与决策要点（用于密钥续期/更换场景）。
- **FR-016**: 申请地址可能随服务商调整而失效；界面 MUST 同时呈现可读的服务商名称与域名，使用户可自行检索最新入口，链接失效 MUST NOT 阻断配置流程。

**C. 运行时风险透明（用户故事 3）**

- **FR-017**: 渠道界面 MUST 以标签或说明区分接入方式（官方 API / 网页解析型），使用户无需外部资料即可理解两类渠道的稳定性与合规差异。
- **FR-018**: 渠道失败原因 MUST 可区分呈现（至少区分：限流、风控封禁、网络不可达、解析失败），供用户判断处置（换渠道/挂代理/调整配置）。
- **FR-019**: 渠道页面的指引信息（推荐顺序、可用性结论等）MUST 与本特性交付的渠道集合保持一致；MUST NOT 包含已过时或相矛盾的结论（如"该类渠道均不可用"）。
- **FR-020**: 免密钥网页解析型渠道的"非官方接入"性质与合规责任 MUST 在使用界面明示（沿用既有兜底渠道的提示口径）。

### Key Entities *(include if feature involves data)*

- **渠道类型模板（预置）**：每种渠道类型的元信息——显示名、默认端点、密钥需求（含"无需"）、官方密钥申请地址、接入方式（官方 API / 网页解析型）、适用市场与定位、免费额度与条款要点、风险提示。新增字段支撑 FR-013~FR-017。
- **检索渠道实例（沿用既有实体）**：用户添加的渠道（类型、名称、优先级、启停、健康、当日用量）；免密钥类型的实例不含密钥，可携带语言/语区参数。
- **检索结果条目**：标题、已还原的目标链接、摘要（可得时）、来源渠道标记。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户从零添加一个免密钥渠道并完成连通测试 ≤ 1 分钟，全程无需离开应用查阅任何外部资料。
- **SC-002**: 六个免密钥引擎在相应网络可达条件下逐一实测，均可完成真实查询并返回 ≥1 条含"标题 + 可直接访问链接"的结果（验收覆盖全部 6 个引擎）。
- **SC-003**: 对风控类响应样本（人机校验/拦截/限流/伪装页）回放验证：进入线索数据的有害数据为 0 条，且全部样本被正确判为失败并可复现。
- **SC-004**: 混合渠道配置（付费 + 免费）下，单渠道失败引起的任务中断为 0 次（故障转移链中存在健康渠道时）。
- **SC-005**: 需要密钥的预置渠道 100% 提供官方申请地址；从渠道界面单击一次即在系统浏览器打开对应申请页面。
- **SC-006**: 免密钥渠道结果链接还原有效率 ≥ 95%（对固定样本页面集核验：链接直接指向结果站点、无需人工二次跳转）。
- **SC-007**: 渠道界面 100% 标注各类型的接入方式与性质提示；抽测用户可据此说明"哪类渠道更稳定、为什么免费"，无需外部资料。

## Assumptions

- **框架复用**：检索渠道模型、优先级故障转移、健康/用量统计、密钥加密存储均为既有能力（001 已交付），本特性在此基础上扩充渠道类型与信息呈现；既有 DuckDuckGo 兜底渠道纳入统一呈现与管理，不重复建设。
- **不预置、不自动调用**：免费渠道以"预置模板"提供，由用户主动添加后生效；不默认预置任何渠道实例，也不自动发起任何请求（对齐"对外调用由用户主动触发且可见可控"的既有原则）。
- **网络可达性**：目标服务的可达性取决于用户网络环境；受限网络（如中国大陆访问 Google）需用户自备代理（工具支持代理配置），产品不内置任何规避手段。
- **非官方接入的性质**：免费网页解析型渠道的结果质量与可用性受服务商页面结构、反爬策略影响；产品承诺"安全失败、可自动切换、可诊断"，不承诺持续可用或与官方 API 等同的稳定性（Bing 搜索 API 已退役、Google PSE 已对新客户关闭，网页途径是零成本访问的主要方式）。
- **Wikipedia 特殊性**：Wikipedia 具备官方免密钥数据接口，性质上与抓取型渠道不同、预期更稳定；其接入形态（官方接口与网页途径的取舍）由实现阶段择优，规格只约束"免密钥可用 + 条目粒度结果"。
- **官方接口优先**：Mojeek 等引擎若存在可用的官方免费接口，实现阶段优先官方接口；否则以网页解析方式接入。
- **合规责任**：抓取与使用结果须遵守各服务商条款（部分服务商对结果存储/再分发有限制）；产品以频率限制与界面提示支持合规，最终责任在用户（沿用既有口径）。
- **申请地址维护**：申请地址由维护者在预置数据中定期核对；失效时的兜底呈现见 FR-016。
- **语言默认**：渠道未显式配置语言/语区参数时，按引擎默认行为执行，不强制注入。
