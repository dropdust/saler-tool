# Feature Specification: 通用销售获客工具（本地桌面版）

**Feature Branch**: `001-sales-tool`

**Created**: 2026-10-10

**Status**: Draft

**Input**: 用户描述：将现有面向电力金具行业的获客项目（爬虫种子库 + 买家联系方式爬取 + 多语种营销邮件）通用化为一个销售工具。具体需求如下：① 爬虫种子管理：使用知识图谱和词表方式管理，用户可以手动添加，也可以通过大模型获取，也可以通过搜索引擎获取；② 客户信息爬取模块：基于种子，通过搜索引擎、企业黄页等平台爬取目标客户，并从网页中抽取用户的邮箱、电话、WhatsApp、Facebook 等联系方式；③ 营销内容管理：营销邮件、社交媒体消息、短信等群发内容管理；④ 营销通道管理：销售自己的邮箱、短信通道、社交媒体帐号，用这些信息发送营销消息；⑤ 营销计划管理：使用哪个通道发送什么营销内容、发送给多少客户。需要配置大模型密钥，方便使用大模型能力。项目需要封装为一个应用，需要在 Windows、Linux 和 macOS 上运行，后台语言尽量使用 Python，app 前端使用 TypeScript，框架选型 Vue。该项目数据资产保留在用户侧。后续开发升级版本，提供 Web 服务，企业可以统一维护数据资产。

**范围说明（v1）**：本产品把"行业专用的获客工具链"通用化为面向任意行业的"找客户 → 触达客户"销售工作台，核心链路为：种子知识库 → 客户线索挖掘 → 联系方式提取 → 营销内容 → 营销通道 → 营销计划批量触达。v1 为单用户本地桌面应用，数据资产保留在用户侧。关键范围决策（用户确认）：**邮件发送为第一优先级（P0）通道**；短信通道同期提供；**社交媒体（WhatsApp/Facebook 等）消息发送推迟到二期**，v1 仅抽取、展示与导出社媒联系方式供人工跟进。

## Clarifications

### Session 2026-10-10

- Q: 爬虫种子环节，大模型需要承担哪些工作、深入到什么程度？ → A: 使用大模型的知识图谱能力扩充种子；使用大模型能力将中文种子翻译为外文。
- Q: 营销文案（邮件、短信等群发内容）环节，大模型应该以什么粒度参与生成与翻译？ → A: 主题级多语言生成（中文母版 → 各语言版本，人工审校后群发；逐客户个性化不在 v1 范围）；中文母版文案本身也需大模型辅助编写。

### Session 2026-10-11

- Q: 营销计划的"定时发送"（FR-046 节奏选项、Edge Case"定时发送与多时区"）在 v1 如何落地？ → A: 经 `/speckit-analyze`（T146）确认：**v1 仅实现"确认后立即启动"**；`schedule` 字段与界面位保留（向导中标注"后续版本"），定时调度与多时区语义推迟二期（与社媒消息发送同期）。FR-046 的其余节奏能力（目标数量、每日上限、分批节流）均在 v1 范围。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 目标画像与种子知识库（爬虫种子管理）(Priority: P1)

销售人员进入一个新行业或新市场时，首先要回答"我卖什么、卖给谁、卖到哪里"。用户以知识图谱方式维护目标市场画像：产品/产品线（我卖什么）、客户角色（谁采购，如电力施工方、EPC 总包、进口商、经销商）、市场/国家地区、具名机构实体（具体潜在买方组织，如各国电网公司、经销商、展会/协会），并为每个节点维护多语言词表（名称、别名、同义词、行业术语）。系统据此生成"爬虫种子"（结构化搜索词）：用户可以手工添加，可以让大模型基于其知识图谱能力扩充候选种子与实体，也可以从外部检索结果中扩充发现；大模型可将中文种子与词表翻译为各目标语言版本。种子/实体可借助外部公开来源做真实性校验并标注置信度与来源；每条种子记录执行状态与产量（带来多少候选公司、多少联系方式），用于排序与淘汰；图谱提供可视化视图，便于识别已覆盖与空白市场。

**Why this priority**: 种子质量直接决定线索质量与精度（行业经验：直接列举具名买方实体远优于"产品词×泛角色词"的泛搜）；种子知识库是"通用化"的关键——换行业只需重建图谱；该模块独立可用：种子可导出到任意外部渠道执行并回灌产量。

**Independent Test**: 以一个全新行业（非电力金具类目）为例，不使用任何已有数据，完成"建模 → 生成种子 → 校验 → 可视化 → 导出"全流程，获得一份可执行的种子清单与覆盖率视图。

**Acceptance Scenarios**:

1. **Given** 全新行业中尚无任何数据，**When** 用户创建产品线、客户角色、市场/国家节点并手工补录若干种子，**Then** 图谱与种子列表实时更新，每条种子带有分类（产品线/客户角色/市场/语言）、优先级与状态。
2. **Given** 已配置大模型服务，**When** 用户输入行业/产品/市场描述并要求扩充种子，**Then** 系统基于大模型的知识图谱能力产出候选种子与候选实体，并将中文候选翻译为目标语言版本后进入"待审核"区，用户可逐条采纳、修改或拒绝后入库。
3. **Given** 某批种子已执行（本工具内执行或导出到外部执行后回灌），**When** 用户查看种子统计，**Then** 每条种子显示产量（候选公司数/联系方式数），可按产量排序并识别出零产出种子以便调整或淘汰。
4. **Given** 图谱中已有多类节点与关系，**When** 用户打开图谱视图，**Then** 可按市场/批次筛选，颜色或大小反映已覆盖率与产量，能一眼识别已收割市场与空白市场。

### User Story 2 - 客户线索挖掘与联系方式提取 (Priority: P2)

基于选定的种子，系统自动在搜索引擎、企业黄页/商业目录及目标公司官网上挖掘目标客户，形成线索列表，并从公开网页抽取联系方式：邮箱、电话、WhatsApp、Facebook（体系可扩展更多渠道）。联系方式按用途分类（如采购/销售/通用/其他），同一公司内的重复联系方式自动去重合并；为每家公司补全国家/地区与使用语言；用户可用排除规则过滤同行、供应商与无关站点，可人工审核修订线索；任务支持断点续跑与进度日志；线索可导出为表格（Excel/CSV）。

**Why this priority**: "可触达的客户名单"是获客的核心产出物，也是后续内容、通道、计划模块的数据来源；没有线索，后面所有模块都无米下锅。

**Independent Test**: 手工输入少量种子（或选用 US1 导出的种子）→ 运行一次挖掘任务 → 得到去重后的公司与联系方式列表并可导出；全过程不需要内容与通道模块。

**Acceptance Scenarios**:

1. **Given** 用户选定一批种子，**When** 启动挖掘任务，**Then** 系统持续产出候选公司记录（名称、域名、来源、命中种子），并逐步补全国家、语言与联系方式列表，进度与统计实时可见。
2. **Given** 任务因退出应用或断网而中断，**When** 用户重新启动任务，**Then** 任务从中断处继续，已完成目标不重复抓取。
3. **Given** 抓取到多条联系方式，**When** 用户查看某公司，**Then** 同一公司同一联系方式仅保留一条（去重），并按类型（邮箱/电话/WhatsApp/Facebook）与用途分类展示，注明来源页面。
4. **Given** 线索中混入同行/供应商/无关站点，**When** 应用排除规则（关键词、域名、名单），**Then** 这些实体被移出买家列表单独存放，且不会进入后续营销人群。
5. **Given** 线索经人工审核修订，**When** 用户执行导出，**Then** 得到含公司、域名、国家、语言、联系方式、来源与状态的结构化表格（字段可选）。

### User Story 3 - 大模型接入与应用数据管理 (Priority: P2)

用户在"设置"中配置一个或多个大模型服务（服务商、API 密钥、模型/接入地址），并可一键测试连通性；密钥本地加密存储、界面脱敏显示。未配置大模型时，所有手工与规则功能完整可用，AI 入口明确提示"需配置模型"。用户可指定数据资产在本机的存储位置，并对全部数据执行备份、恢复与导出；更换电脑后可完整迁移（种子图谱、线索、内容、通道配置、发送台账与设置）。应用为本地优先：不强制上传任何业务数据到服务器；调用外部大模型前，明确提示哪些数据将发送出去。

**Why this priority**: 大模型是种子扩充、文案辅助编写与多语言生成等增强能力的前置条件；"数据资产保留在用户侧"是用户明确的第一原则，备份与迁移能力是其落点；该模块独立可测且被其他多个模块依赖。

**Independent Test**: 全新安装后：选择数据目录 → 配置大模型密钥并测试通过 → 成功让大模型扩充出一批候选种子；执行一次备份，并在另一环境恢复后校验数据完整。

**Acceptance Scenarios**:

1. **Given** 用户持有某大模型服务密钥，**When** 录入并测试连通性，**Then** 显示连接成功或可操作的失败原因；密钥在界面、日志与导出物中均不以明文出现。
2. **Given** 未配置任何大模型服务，**When** 用户使用手工建模、规则抓取与发送功能，**Then** 全部可用；AI 功能入口给出"需先配置模型"的明确提示。
3. **Given** 本机已有完整数据，**When** 用户执行备份并在另一台电脑恢复，**Then** 种子图谱、线索与联系方式、营销内容、通道配置、发送台账与设置完整还原。
4. **Given** 用户需要更换数据存储位置，**When** 指定新位置，**Then** 数据被完整迁移且校验通过，后续读写指向新位置。

### User Story 4 - 营销内容管理 (Priority: P3)

销售人员维护群发内容：营销邮件、社交媒体消息、短信。同一内容主题可维护多语言版本（面向不同国家客户自动匹配），正文支持变量占位（公司名、联系人、产品名、签名等）；大模型深度参与内容生产：辅助销售编写中文母版（起草、润色、多角度改写），并以主题级粒度一次生成/翻译各目标语言版本（结果须人工审核后才可发布）；内容支持版本迭代与历史回溯、草稿/待审核/已发布/已归档状态管理；发送前可预览（变量渲染后的最终效果）并测试发送。

**Why this priority**: 内容是与客户沟通的"弹药"，多语言版本直接决定非英语市场的触达效果；该模块不依赖任何发送通道即可独立开发与验收。

**Independent Test**: 创建一个内容主题：由大模型辅助起草中文母版，并生成英文与第三种语言版本；插入变量并预览，审核后发布；全过程无需连接任何发送通道。

**Acceptance Scenarios**:

1. **Given** 用户新建营销内容，**When** 编写正文（手工撰写，或由大模型辅助起草/润色）并插入变量占位，**Then** 内容进入草稿状态，可预览变量替换后的渲染效果。
2. **Given** 同一主题存在多语言版本，**When** 制定发送策略，**Then** 可按客户的"使用语言"自动匹配对应版本；缺失语言时按明确回退策略（默认语言）发送并在台账中标注。
3. **Given** 已发布内容被再次修改，**When** 用户保存，**Then** 系统生成新版本，历史版本可查看、回溯与恢复。
4. **Given** 内容仅供草稿或因 AI 生成处于待审核状态，**When** 用户尝试在营销计划中选用，**Then** 系统拒绝并提示"未发布内容不可用于发送"。

5. **Given** 中文母版已定稿（可由大模型辅助编写），**When** 用户指定目标语言并要求生成多语言版本，**Then** 系统以主题级粒度一次产出所选语言版本（主题行与正文），保留母版与各语言版本的血缘关系，供人工审校后发布；不要求逐客户生成。

### User Story 5 - 营销通道管理（邮箱与短信）(Priority: P4)

销售人员登记并管理自有发送通道：邮箱通道（发信服务器、账号、授权码等配置）与短信通道（服务商凭证配置）。配置后可执行连通性测试/凭证校验，并显示健康状态；可设置发件人身份（名称、签名、回复地址）与发送限制（每日上限、发送频率、并发数）；支持多个同类型通道并存（如多个发件邮箱），分别记录用量与额度。邮件发送是 v1 的第一优先级（P0）能力；社交媒体账号与消息发送列入二期。

**Why this priority**: 通道是把内容送达客户的"管道"，是"发出邮件"这一 P0 能力的直接载体；每类通道可独立配置与测试，先于营销计划模块。

**Independent Test**: 配置一个邮箱通道并测试连接成功、发送测试邮件到用户自己；再配置一条短信通道并完成测试发送；全过程不需要线索与计划模块。

**Acceptance Scenarios**:

1. **Given** 用户拥有邮箱授权凭证，**When** 完成配置并测试，**Then** 显示连接成功，或给出可操作的失败原因（服务器/端口/授权/网络等）。
2. **Given** 通道设置了每日上限，**When** 后续计划的发送量将超过上限，**Then** 系统组织排队/分批策略并明确提示，不会超量发送。
3. **Given** 用户配置了多个发件邮箱，**When** 创建营销计划，**Then** 可选择具体发件人身份；各通道的已用额度分别可见。
4. **Given** 通道凭证已保存，**When** 用户查看界面或日志、导出任何数据，**Then** 凭证始终脱敏，不以明文出现。

### User Story 6 - 营销计划与批量触达（邮件优先）(Priority: P5)

销售人员创建营销计划：选择目标人群（按筛选条件/标签/来源圈定客户）、选择营销内容（含语言策略）、选择发送通道（v1 以邮件为主、短信可选），设定发送数量与节奏（立即或定时、每日上限、分批执行）。创建时系统给出影响范围预估（覆盖客户数、消息条数、按语言/通道分布）；执行中实时显示进度与成功/失败统计，支持暂停、中止、恢复；失败项可重试。系统维护发送台账（谁、在哪个计划、哪一轮次、何时、经哪个通道、收到哪一版内容、结果），自动防止同一客户重复打扰；提供退订/黑名单管理，后续计划自动排除；支持多轮跟进序列（首轮未获"回复/进展"标记的客户按间隔进入下一轮）。整条邮件发送链路为 v1 最高优先级交付目标。

**Why this priority**: 该模块是前五个模块的集成出口（"用哪个通道、发什么内容、发给多少客户"），直接产生业务价值——把线索变成被触达的商机；邮件发送（P0）在此闭环完成。

**Independent Test**: 用测试客户数据（本人/同事邮箱）走通：圈人群 → 选内容 → 选通道 → 发送 → 查看台账与统计；随后再执行一次相同人群，确认默认不重复发送。

**Acceptance Scenarios**:

1. **Given** 已有线索、已发布内容与可用通道，**When** 用户创建计划并设定数量与节奏，**Then** 系统展示影响范围预估（客户数、消息条数、语言/通道分布、预计时长）供确认后执行。
2. **Given** 计划执行中，**When** 用户查看进度，**Then** 实时显示已发送/失败/跳过/剩余数量与失败原因，并可暂停、中止、恢复。
3. **Given** 某客户已在同一轮次收到消息，**When** 生成新的计划或重跑，**Then** 系统默认跳过该客户；重发须显式允许并在台账留痕。
4. **Given** 客户提出退订或邮箱退信，**When** 加入黑名单/标记状态，**Then** 该联系方式在所有后续计划中自动排除，不再收到任何消息。
5. **Given** 计划配置了多轮跟进，**When** 首轮完成且客户没有"已回复/有进展"标记，**Then** 按设定间隔自动进入下一轮并发送对应轮次内容；已标记回复/成交/拒绝的客户不再进入后续轮次。
6. **Given** 计划执行完成，**When** 用户查看报表，**Then** 可查看并导出台账与统计（按通道/语言/批次/轮次的发送量、成功率与失败原因分布）。

### Edge Cases

- 无网络或代理不可用：抓取与发送任务暂停并明确提示原因；网络恢复后可从中断处继续。
- 检索渠道风控、限流或验证码拦截：任务自动降速或切换可用渠道；持续失败时提示用户更换渠道或稍后再试，不产生脏数据。
- 目标网页结构各异或含反爬混淆（邮箱为图片、脚本拼接、防爬噪点）：尽力提取并清洗；无法确证的提取结果标注低置信度供人工复核。
- 大模型密钥无效、余额不足或限流：给出明确报错与重试建议；手工与规则功能不受影响；AI 批量产出内容必须经人工审核才可发布，防止事实性错误直接发出。
- 发送失败、退信或通道被服务商限制：记入台账并标注原因；支持重试或改用其他可用通道；当日额度触顶时自动排队到下一时间窗并提示。
- 同一公司有多个域名、同一联系方式出现在多个页面：按合并规则去重，避免同一联系人在不同计划中被重复打扰。
- 数据存储目录不可写或磁盘空间不足：任务开始前检查并阻止启动，给出可操作提示；不进入部分写入的中间状态。
- 备份文件损坏或版本不兼容：恢复前执行校验，校验失败时明确报错且不影响现有数据。
- 内容缺少客户所需语言版本：按回退策略使用默认语言发送，并在发送台账中标注"回退"。
- 定时发送与多时区：调度以用户本地时区定义并在界面明示，避免歧义。
- 数据规模增长（上万条种子、十万级线索）：列表、筛选与图谱视图保持可接受的响应速度（分页/按需加载）。
- 用户误把同行/供应商当目标：排除规则与"中国同业/供应商"清单机制兜底，并支持事后批量移出。

## Requirements *(mandatory)*

### Functional Requirements

#### 通用与平台要求

- **FR-001**: 应用必须以本地桌面应用形态交付：用户在 Windows、macOS、Linux 上无需安装开发环境即可安装、启动与使用，且三个平台功能一致。
- **FR-002**: 所有业务数据默认保存在用户本机并可由用户指定存储位置，包括：种子与图谱、客户线索与联系方式、营销内容、通道配置与凭证、发送台账、大模型密钥配置。
- **FR-003**: 应用不得强制依赖任何云端服务账号；除用户主动使用外部能力（检索、大模型、发送）外，离线状态下仍可查看与管理已有数据、编辑内容。
- **FR-004**: 系统必须支持数据资产的完整备份、恢复与导出（开放格式），支持更换设备迁移；应用升级不得丢失或损坏既有数据；导出能力须为未来"企业 Web 服务统一维护数据资产"预留迁移路径。
- **FR-005**: 界面以中文提供，面向业务人员设计（不假设用户具备开发能力）；关键操作须提供清晰的进度、结果与错误提示。
- **FR-006**: 敏感凭证（大模型密钥、邮箱授权码、短信服务商凭据）必须加密存储、界面脱敏展示，且不得出现在日志、报错信息或导出文件中。

#### 种子知识库（US1）

- **FR-007**: 必须支持以图谱结构组织目标市场知识，节点类型至少包括：产品/产品线、客户角色（买方画像）、市场/国家地区、具名机构实体（具体潜在买方组织，如电网公司、EPC 总包、经销商、展会/行业协会等）。
- **FR-008**: 图谱节点之间必须支持建立关系（如产品线与客户角色的适配关系、机构实体归属市场），关系参与种子生成并用于约束无效组合。
- **FR-009**: 必须为节点维护词表：多语言名称、别名、同义词与行业术语，用于生成多语言搜索词；多语言词表须支持由大模型从中文母版翻译生成，并可人工校对修订。
- **FR-010**: 种子的定义 = 搜索词或查询模板 + 分类维度（产品线、客户角色、市场/国家、语言、优先级、批次）+ 状态；同一搜索词不得重复入库。
- **FR-011**: 用户必须能够手工新增、编辑、合并、停用种子与图谱节点。
- **FR-012**: 系统必须支持通过大模型扩充种子与翻译：① 基于大模型的知识图谱能力，从行业/产品/市场描述或已有图谱节点出发，扩充产出新的候选机构实体与候选种子；② 支持将中文种子与词表由大模型翻译为目标语言版本，并可人工校对。候选统一进入待审核清单，可逐条采纳、修改或拒绝后入库。
- **FR-013**: 系统必须支持通过外部检索扩充图谱：从搜索结果与目录中提炼新的机构实体与种子并沉淀入库，同时记录来源。
- **FR-014**: 必须支持对种子与机构实体进行真实性/相关性校验（借助外部公开来源佐证），标注置信度与来源供人工复核；低置信度对象默认不进入正式执行队列。
- **FR-015**: 每条种子必须具备生命周期状态（待执行/执行中/已完成/无效）与产量统计（产生的候选公司数、产出的联系方式数），支持按产量排序、识别零产出种子并据此调整优先级。
- **FR-016**: 种子必须可导出为执行清单，外部执行结果必须可回灌（更新状态与产量），兼容"外部工具/人工执行收割"的工作方式。
- **FR-017**: 必须提供图谱可视化：结构视图（产品线-客户角色-市场）与实体视图（机构实体-市场）；支持按市场/批次筛选；以颜色或大小反映覆盖率与产量，可直观识别空白市场。
- **FR-018**: 必须支持批量导入既有种子、词库与实体清单（表格或文本格式）。

#### 客户线索挖掘与联系方式提取（US2）

- **FR-019**: 基于选定的种子，必须能够通过可配置的检索渠道（搜索引擎、企业黄页/商业目录、第三方检索服务）发现候选目标公司，并记录来源与命中的种子。
- **FR-020**: 必须访问候选公司的公开网页（含常见联系页面）抽取联系方式：邮箱、电话、WhatsApp、Facebook；体系须可扩展更多渠道（如 LinkedIn、X/Twitter、Instagram、微信等）。
- **FR-021**: 联系方式必须按类型与用途分类（如采购/销售/通用/其他），同一公司内重复联系方式必须去重合并；对格式异常的联系方式做基础清洗并标注"疑似无效"。
- **FR-022**: 每家公司必须维护画像：名称、域名、国家/地区、使用语言、来源页面、联系方式列表、审核与触达状态。
- **FR-023**: 必须支持排除规则（关键词、域名、名单）过滤同行/供应商/无关站点；被排除对象单独存放，不进入营销人群。
- **FR-024**: 挖掘任务必须支持断点续跑、失败重试、暂停/恢复，且对同一目标不重复抓取。
- **FR-025**: 抓取行为必须可配置频率与并发上限（礼貌抓取），并支持网络代理配置（用于访问海外站点）。
- **FR-026**: 任务必须展示进度与统计（候选数、成功/失败、联系方式产出率），并保留可查阅的执行日志。
- **FR-027**: 线索列表必须支持筛选、搜索与人工修订（补录、纠错、状态标记：新线索/已联系/已回复/无效/已退订等）。
- **FR-028**: 线索必须可导出为结构化表格（Excel/CSV），支持自选字段。
- **FR-029**: 必须支持导入既有客户名单（表格文件）与外部线索结果，纳入统一客户库并参与去重与黑名单检查。

#### 大模型接入与数据管理（US3）

- **FR-030**: 用户必须能够配置一个或多个大模型服务（服务商、API 密钥、模型/接入地址），并可测试连通性与可用性。
- **FR-031**: 大模型的能力使用点至少包括：种子与实体的知识图谱扩充、中文种子/词表翻译（US1）、中文母版文案辅助编写与主题级多语言生成/翻译（US4）；每次调用外部大模型前，涉及的数据范围必须对用户可见、可控。
- **FR-032**: 未配置大模型时，所有非 AI 功能（手工管理、规则化抓取、发送）必须保持完整可用。
- **FR-033**: 用户必须能够选择/更改数据存储位置并完成迁移；业务数据默认不上传至任何服务端。

#### 营销内容管理（US4）

- **FR-034**: 必须支持管理多类群发内容：营销邮件、社交媒体消息、短信；每条内容含主题（如适用）与正文，并归属于一个内容主题（可含多语言版本）。
- **FR-035**: 内容必须支持变量占位（公司名、联系人、产品、签名等），预览与发送时按客户数据渲染。
- **FR-036**: 同一主题必须支持多语言版本管理；发送时必须能按客户的"使用语言"自动匹配版本，缺失语言时按明确回退策略（默认语言）处理并在台账标注。
- **FR-037**: 内容必须支持版本管理：修改产生新版本，历史版本可查看与恢复；状态含草稿/待审核/已发布/已归档；未发布内容不可被营销计划选用。
- **FR-038**: 必须支持借助大模型辅助编写中文母版（起草/润色/改写），并以主题级粒度一次生成/翻译出各目标语言版本（翻译应复用词表术语，保持产品名与行业术语的多语言一致）；AI 生成结果必须经人工审核后才可发布使用；v1 不要求逐客户个性化生成。
- **FR-039**: 发送前必须支持预览（变量渲染后的最终效果）与测试发送。

#### 营销通道管理（US5）

- **FR-040**: 用户必须能够登记、编辑、启停自有发送通道：邮件通道（发信服务器、账号、授权码等）与短信通道（服务商凭证）；系统须为二期接入社交媒体通道预留扩展。
- **FR-041**: 通道配置后必须可执行连通性测试/凭证校验，并展示健康状态与最近检测结果。
- **FR-042**: 每类通道必须支持配置发送限制：每日上限、发送频率、并发数。
- **FR-043**: 通道必须支持发送身份配置：发件人名称、签名、回复地址（按通道适用性）。
- **FR-044**: 必须支持多个同类型通道并存（如多个发件邮箱），并分别记录用量与额度。
- **FR-045**: v1 自动发送范围 = 邮件通道（第一优先级，P0）+ 短信通道；社交媒体（WhatsApp/Facebook 等）消息发送列入二期规划，v1 必须支持社媒联系方式的抽取、展示与导出（供人工跟进）。

#### 营销计划与批量触达（US6）

- **FR-046**: 必须支持创建营销计划：选择目标人群（按筛选条件/标签/来源圈定）、选择内容主题与语言策略、选择发送通道，并设定目标数量与发送节奏（立即/定时、分批、每日上限）。
- **FR-047**: 创建计划时必须给出影响范围预估：覆盖客户数、消息条数、按语言/通道分布与预计执行时长，供用户确认。
- **FR-048**: 执行中必须显示实时进度与统计（成功/失败/跳过/剩余）及失败原因；支持暂停、中止、恢复。
- **FR-049**: 必须维护发送台账：记录每位客户在每个计划、每个轮次中收到哪一版内容、经哪个通道、何时发送、结果如何。
- **FR-050**: 必须自动防止重复打扰：同一客户在同一轮次默认不重复发送；重发须显式允许并在台账留痕。
- **FR-051**: 必须提供退订/黑名单管理；命中对象在所有后续计划中自动排除。
- **FR-052**: 计划必须支持多轮跟进：未获得"回复/进展"标记的客户按设定间隔进入下一轮，使用对应轮次内容。
- **FR-053**: 计划必须支持执行前审核与试发（小批量测试）；计划台账与统计可导出。
- **FR-054**: 客户互动状态（已回复、已成交、明确拒绝等）必须可人工标记，并立即作用于后续跟进与排除逻辑。

### Key Entities *(include if feature involves data)*

- **图谱节点（Graph Node）**：类型（产品线/客户角色/市场/机构实体）、名称、多语言词表（别名/同义词/术语）、属性、置信度、来源。
- **图谱关系（Graph Relation）**：起点节点、终点节点、关系类型（如适配、归属）。
- **种子（Seed）**：搜索词/查询模板、分类（产品线/客户角色/市场/语言/优先级/批次）、状态、产量统计（候选公司数/联系方式数）、来源（手工/大模型/检索）、审核状态、置信度。
- **校验记录（Validation Record）**：被校验对象、佐证来源、结论、置信度、时间。
- **挖掘任务（Crawl Job）**：种子范围、状态、进度、统计、日志、起止时间。
- **客户/线索（Company/Lead）**：名称、域名、国家、语言、来源、标签、审核状态、触达状态、排除标记。
- **联系方式（Contact）**：类型（邮箱/电话/WhatsApp/Facebook/…）、值、用途分类、来源页面、置信度、黑名单标记。
- **营销内容（Content）**：类型（邮件/社媒/短信）、所属主题、语言版本（中文母版与各目标语言版本，含血缘关系）、主题行/正文、变量、版本、状态（草稿/待审核/已发布/已归档）。
- **发送通道（Channel）**：类型（邮件/短信/社媒[二期]）、凭证（加密）、发送身份、限额与频率、健康状态、用量。
- **营销计划（Campaign）**：目标人群条件、内容与语言策略、通道、数量与节奏、调度、状态、预估与结果统计、跟进轮次配置。
- **发送记录（Send Record）**：客户、计划、轮次、内容版本、通道、时间、结果、失败原因。
- **退订/黑名单（Suppression）**：对象（联系方式或公司）、原因、来源、时间。
- **排除规则（Exclusion Rule）**：类型（关键词/域名/名单）、内容、启用状态。
- **大模型配置（LLM Configuration）**：服务商、密钥（加密）、模型/接入地址、状态。
- **应用设置（App Settings）**：数据目录、网络代理、界面语言、内容回退语言等。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 全新行业（非电力金具类目）从零开始，用户可在 1 个工作小时内完成产品线/客户角色/市场建模，并获得 ≥100 条经审核可执行的种子（且至少来自手工添加、大模型扩充、检索发现中的两种渠道）。
- **SC-002**: 单个用户在 1 个工作日内可完成首次端到端闭环：配置 → 挖掘出 ≥500 家候选公司 → 产出 ≥300 个可用联系方式 → 创建多语言内容并配置通道 → 发出首批 ≥200 条营销邮件。
- **SC-003**: 挖掘任务的联系方式命中率达到：每家企业域名平均产出 ≥1.2 个可用邮箱（对标现有行业项目实测水平 1.2–1.5）；任务中断恢复后重复抓取记录为 0。
- **SC-004**: 同一客户在同一轮次内收到重复消息的比例为 0；退订/黑名单生效后再次触达的比例为 0。
- **SC-005**: 备份数据在另一台设备恢复后，种子、线索、内容、通道配置与发送台账的完整一致率达到 100%；应用升级后数据无损。
- **SC-006**: Windows、macOS、Linux 三个平台上均可完成安装、启动并通过完整核心流程（三平台功能一致）。
- **SC-007**: 单机环境下流畅管理 ≥10,000 条种子与 ≥100,000 条客户线索（列表滚动、筛选、搜索保持可接受响应）。
- **SC-008**: 借助大模型一次操作可从中文母版产出 ≥3 种语言版本的内容，经人工审校后可直接用于发送。
- **SC-009**: 从开始录入凭证到测试发送成功，邮箱/短信通道配置耗时 ≤10 分钟。
- **SC-010**: 在未配置大模型的前提下，"手工建模 → 种子 → 挖掘 → 内容 → 发送"的完整链路仍可完成（AI 仅为增强，不构成单点依赖）。
- **SC-011**: 新用户无需阅读外部文档、仅凭应用内提示，可在 30 分钟内完成"首个营销计划"的创建与试发。

## Assumptions

- 产品定位为 B2B 主动外联获客（找企业客户 → 找联系人 → 外联触达），不面向 B2C 消费者营销与无差别群发场景。
- v1 为单用户本地桌面应用，不含多用户、权限与协作能力；"企业统一维护数据资产"的 Web 服务版本为后续规划，v1 以保证数据可导出、可迁移的方式为其预留。
- 用户明确：**邮件发送为 v1 第一优先级（P0）；社交媒体消息发送推迟到二期**；v1 通道管理的自动发送范围为邮件与短信。
- 仅处理公开可访问的网页信息；不涉及登录墙/付费墙后的数据。
- 用户自行准备并负责：大模型服务密钥与费用、邮箱发信凭证、短信服务商账号、（可选）网络代理；工具不内置上述账号。
- 检索渠道（搜索引擎/黄页/第三方检索服务）的可用性与覆盖率取决于用户所处网络环境与所配置的服务；系统提供多渠道配置与失败降级提示，不承诺任一渠道永久可用。
- 合规主体责任在用户：发送内容与频率需遵守目标市场法规（如反垃圾邮件、个人信息保护相关法律）与平台条款；系统提供退订/黑名单、发送限频、来源审计等合规支持工具，但不替代用户的合规判断与法律责任。
- 客户"回复"的识别在 v1 采用人工标记（与现有工作方式一致），不做收件箱自动监控；后续版本可扩展自动识别。
- 数据模型聚焦"线索与触达管理"，不含完整 CRM 能力（商机、合同、售后服务等不在 v1 范围）。
- 界面语言以中文为主；营销内容支持多语言（以目标市场常见语种为准，如英语、俄语、阿拉伯语、西班牙语、法语、葡萄牙语等）。
- 现有电力金具项目（runte）的种子、客户与发送台账数据可作为首个导入样例，用于验证迁移与兼容；其业务经验（具名实体种子、按客户语言匹配内容、发送台账防打扰等）作为本产品的设计输入。
- 用户在需求中明确了技术方向：后端 Python、前端 TypeScript + Vue，封装为可在 Windows/Linux/macOS 运行的桌面应用；具体技术方案、打包与发布方式属于技术规划阶段内容，本规格不做限定。
