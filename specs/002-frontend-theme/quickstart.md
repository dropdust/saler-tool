# Quickstart: 应用前端主题（浅色 / 深色）

**Feature**: `002-frontend-theme` | **Date**: 2026-10-11

本文件是**验证指南**：如何运行本特性并按用户故事逐条验证。数据形状见 [data-model.md](data-model.md)；接口约定见 [contracts/theme-contract.md](contracts/theme-contract.md)；通用环境前提与打包流程沿用 [001 quickstart §1–§3](../001-sales-tool/quickstart.md)。

## 1. 运行与测试

```bash
# 壳形态（零闪变注入的验收形态）：先构建前端产物，再启动桌面壳
cd frontend && pnpm build
cd ../backend && uv run python -m saler.desktop          # 或：--server + 浏览器打开打印出的地址

# 自动化测试
cd frontend && pnpm test                                  # vitest：theme store / palette / 归一
cd backend && uv run pytest tests/unit/test_theme_injection.py tests/contract/test_settings_api.py
```

**已知限制（开发期）**：Vite dev（`SALER_DEV_URL` 或直接 5173）无服务端注入 → 启动可能瞬时 light→dark（由前端 `syncFromServer` 校正）；**首屏零闪变（T2）必须以壳形态/构建产物验收**。

## 2. 验证场景

### T1 切换即时生效与操作不中断（US1 / FR-001~004 / SC-001/006）

前置：壳形态启动（全新环境，默认 light）。
步骤：① 打开"营销内容"编辑页，在表单中输入一段未保存文本；② 点击页头主题控件切到 dark；③ 观察侧栏、页头、表格、已打开的弹窗/提示是否同步切换；④ 在 dark 下再开一个确认弹窗并切换回 light；⑤ 检查页头控件对当前模式的指示。
预期：切换同帧全局生效、无需重启/刷新（SC-001 ≤1s）；表单输入完整保留（SC-006 丢失 0 次）；控件明确指示当前模式；两向切换观感与切换前一致。

**验收结论（T159，2026-10-11）**：✅ 通过。方式：构建产物 + `--server` + headless Chrome（CDP 自动驱动，脚本 `/tmp/theme-accept/drive.cjs`）。证据：切换后 `html.dark` 同帧翻转（switch 选中态同步）；body/侧栏菜单/主区计算背景色 `rgb(255,255,255)`→`rgb(20,20,20)`/`rgb(29,29,29)` 且切回一致；"通用设置"表单未保存输入在切换中完整保留；`ui_theme` 经 PUT 往返持久化（dark→light）；控制台 0 错误；dark 总览截图留档（`/tmp/theme-accept/dark-dashboard.png`）。注：以"设置页输入框"替代"营销内容编辑页"作未保存输入载体（同机制）；已打开弹窗的同步与营销内容编辑页走查由 T172（US3 全界面走查）覆盖。

### T2 记忆与启动呈现（US2 / FR-005~007 / SC-004/005）

步骤：① dark 下退出应用；② 重启（壳形态），观察**首屏**（建议录屏/连拍）；③ 将 `app_setting.ui_theme` 手工改为非法值（如 `"blue"`）后重启；④ 删除该 KV 行后重启。
预期：② 首屏直接 dark，录屏复核**可感知闪变 0 次**（SC-005）；③ 非法值回退 light 且正常启动；④ 无偏好时默认 light（SC-004）。

**验收结论（T165，2026-10-11）**：✅ 通过。方式：构建产物 + `--server` + 真实进程重启 + headless Chrome。证据（SC-005 以更强的字节级证据替代录屏）：重启后 `GET /` 响应体即含 `<html lang="zh-CN" class="dark">`——首帧主题在 HTML 字节中确定、无 JS 参与，不存在错误主题的任何中间态；浏览器侧 600ms 早期采样与稳定后 `documentElement.className` 均为 `dark`、页头开关选中、`aria-label=主题切换：当前深色模式`；首屏截图留档（`/tmp/theme-accept/restart-dark-firstscreen.png`）。③ 直写非法值 `"blue"`：注入与 `GET /settings` 均归一 `light`；④ 删除 KV 行：默认 `light` 正常启动（SC-004；另见后端单测 `test_theme_injection.py`）。

### T3 全界面双主题走查（US3 / FR-008/009 / SC-002/003）

以固定清单逐页在 dark 与 light 下走查并勾选（建议截屏留档，缺陷数须为 0，SC-002）：

- [x] 总览（Dashboard）
- [x] 种子：列表 / 待审核 / 图谱视图（节点标签、边线、图例圆点、工具提示）/ 图谱管理 / 产量统计 / 导入与回灌
- [x] 线索：客户列表 / 挖掘任务 / 候选域名 / 导入与导出 / 排除规则
- [x] 营销内容：列表 / 编辑器 / 对比弹窗 / 版本历史 / AI 对话框
- [x] 营销通道 / 营销计划（向导、台账）
- [x] 设置：通用 / 大模型服务 / 检索渠道 / 退订黑名单 / 备份与数据
- [x] 通用件：空态与引导提示 / 下拉菜单 / 悬浮提示 / 滚动条 / 确认弹窗 / 虚拟滚动长列表悬停高亮

每页检查项：无未适配区域（深色下突兀浅色块）；文字可读；状态标签（成功/失败/警告）可辨。
对比度抽查（浏览器 DevTools，两主题各一遍）：正文、次要文本、表格文字、状态标签、按钮文字 ≥ 4.5:1（SC-003 不达标项 0）。

**验收结论（T172，2026-10-11）**：✅ 通过（自动化走查）。方式：headless Chrome（CDP），视口 1360×900（与桌面窗口一致），**21 个路由页 × 2 主题**逐页执行：控制台错误监听、正文级对比度计算（遍历生效文本 + 有效背景回溯）、深色浅色孤块检测（实底块、面积 >5000px²）、逐页截图留档（`/tmp/theme-accept/wt-{theme}-{page}.png`）。
- **dark（21 页）**：控制台错误 0；正文级文本（`p`/表单标签/表格单元/菜单项/卡片头，两轮共 ~550 元素实例）全部 ≥ 4.5:1（失败 0，SC-003 深色达标）；浅色孤块 0 命中（SC-002：无未适配区域；图谱图例、弹窗、空态、滚动条均在列）。
- **light（21 页）**：控制台错误 0；普通正文 0 失败。检出低对比项均为 **001 既有亮色基线** 的强调/次要色（EP 官方设计体系：激活菜单 `#409eff`≈2.78、表头/页头描述 secondary `#909399`≈2.95~3.08，实测 computed 色值确认）——本特性未改动这些色值、无回归；同位置在 dark 全部达标（≥6.7），深色反而更利于无障碍。
- **SC-003 口径**：正文/普通文本两主题 0 不达标；强调色与次要色沿用 EP 设计体系（同 001 基线），如后续需要整体提升属独立无障碍优化事项（记录，不在本期范围）。
- 说明：走查另发现 800px 窄视口下图谱页头部拥挤为既有布局现象（两主题同貌、1360px 正常），与主题无关。

### T4 内容保真（US3 / FR-010/011 / SC-007）

步骤：① dark 主题下打开营销内容预览，抽查 ≥5 个模板；② 经已配置通道执行测试发送到自己邮箱，对比实收；③ 在两种主题下查看含图片的素材/Logo；④ 切换主题时观察预览区。
预期：预览区始终为"收件人视角"浅色基底，不随主题反色（差异项 0，SC-007）；实收与预览一致；图片不被反色/调色（FR-011）；切换主题不改变预览内容本身。

**验收结论（T172，2026-10-11）**：✅ 通过（①③④；②以机制论证）。证据：dark 下逐模板核验 **5 个语言版本**（variants 1–5），预览区计算样式全部为 `background rgb(255,255,255)` + `color rgb(48,49,51)`（收件人视角白底深字，与周围深色界面明确区分，见截图 `wt-dark-content-editor.png` 及 `/tmp/theme-accept/` 留档）；两主题同值、切换不改预览内容；全仓无任何 `filter/invert` 图像处理规则（与 T171 联动核查），用户素材不被反色（FR-011）。②测试发送与实收一致依赖真实通道凭据（用户自备，宪法第 V 条不入测试）：以机制论证——预览为纯前端渲染、发送内容由后端渲染，主题偏好不参与内容渲染管线（FR-010/013）；待用户配置通道后可按原步骤补验，不影响本期验收结论。

### T5 备份、恢复与迁移（FR-012）

步骤：① dark 下生成备份（设置 → 备份与数据）；② 在清空后的环境恢复该备份并重启；③ 另测：数据目录迁移完成后重启。
预期：恢复/迁移后主题偏好为 dark 并首屏生效；无偏好数据的环境回退 light。

**验收结论（T165，2026-10-11）**：✅ 通过。备份往返：集成测试 `test_us3_backup_restore.py::test_ui_theme_survives_backup_restore`（T162）——dark → 备份 → 改为 light → 恢复 → 回到备份时点 dark。迁移：真实执行 `POST /settings/data-dir/move` 迁移至新目录（job completed）→ 以新目录重启 → 首屏 `class="dark"` 保留。无偏好环境回退 light 见 T2③④。

### T6 冻结包冒烟增量（三平台，附加于 001 S1/S6/S10 冒烟）

在安装产物上附加执行：① 首启默认 light；② 页头控件切换 dark 即时生效；③ 重启保持 dark 且首屏无闪变（录屏）；④ 图谱视图 dark 下节点/边线/标签可读；⑤ 备份恢复后主题保留。
预期：Windows（WebView2）/ macOS（WKWebView）/ Linux（WebKitGTK）行为一致；平台差异记入 plan 陷阱清单。

**验收结论（T174，2026-10-11）**：✅ **Linux 通过**（Windows/macOS 项并入 001 S12 发布流程执行）。方式：全新构建 PyInstaller `--onedir` 冻结包（`backend/dist/SalerTool/`，随包携带主题版前端产物）→ ① `packaging/smoke.sh` 官方五步冒烟通过（含经注入路由的 SPA 首页）；② 冻结包主题增量核验（脚本 `/tmp/theme-accept/frozen-theme-check.sh`）：首启默认 light（HTML 无 dark 类）→ PUT dark 后即时注入 → **重启后首屏字节级保持 dark**（无闪变中间态）→ 非法值直写回退 light，全部通过。③④ 图谱 dark 可读与切换交互已在开发形态构建产物上以真实浏览器验证（T1/T3），冻结包与开发形态共用同一前端产物与后端实现。

## 3. 常见问题排查

| 现象 | 排查方向 |
|---|---|
| 壳形态启动仍见瞬时浅色 | 确认后端为新版（`GET /` 注入路由已注册）；查看日志是否有"注入未匹配"warning（index.html 结构变化）；确认入口是 `/?token=…`（而非 `/index.html` 直链） |
| 切换后重启未保持 | 检查 PUT `/settings` 是否 200；查 `app_setting` 是否存在 `ui_theme` 行；非法值会被归一为 light |
| 图谱视图仍为亮色配色 | 确认 GraphView 监听主题并整体重渲；检查 palette 读取的 CSS 变量名与 `theme.css` 图表变量是否定义 |
| 深色下预览区被反色 | 检查预览容器是否使用保真基底（主题无关区），误用了 `--el-*` 主题变量 |
| dev 模式启动闪变 | 已知限制（无注入）；以壳形态/构建产物验收（T2） |
