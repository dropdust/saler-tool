## User Scenarios & Testing *(mandatory)*

### User Story 1 - 主题切换与全局即时生效 (Priority: P1)

销售人员在弱光环境下长时间使用应用（如晚间整理客户名单、撰写营销文案），需要更护眼的深色界面；白天办公或对外演示时又希望回到明亮的浅色界面。用户通过应用主界面上的主题切换控件，在 light 与 dark 两种模式间手动切换；切换后整个应用界面（所有页面、弹窗、表格、图表、状态标签、提示等）立即以新主题呈现，无需重启应用，也不中断当前正在进行的操作（如正在填写的表单、正在运行的抓取任务界面）。

**Why this priority**: 这是主题功能的最小可用切片——没有"能切换"就没有主题功能；两种模式直接覆盖用户提出的护眼需求，也是后续记忆与适配质量的载体。

**Independent Test**: 打开应用，从主界面执行一次 light → dark 切换，逐页浏览所有主要页面确认全部界面即时变为深色；再切换回 light 确认恢复；全程不重启、无页面报错、未保存的表单内容不丢失。

**Acceptance Scenarios**:

1. **Given** 应用处于 light 主题，**When** 用户在任意主页面操作主题切换控件，**Then** 全部可见界面（含当前页面、已打开的弹窗与提示）即时切换为 dark 主题，无需重启或刷新。
2. **Given** 应用处于 dark 主题，**When** 用户切换回 light，**Then** 界面恢复为与切换前一致的浅色观感。
3. **Given** 用户正在填写表单（存在未保存输入），**When** 用户切换主题，**Then** 输入内容完整保留，操作不中断。
4. **Given** 用户在任一主页面，**When** 查找主题切换入口，**Then** 无需跳转深层页面即可找到并一步完成操作，且切换控件能明确显示当前所处的主题模式。

---

### User Story 2 - 主题偏好记忆与启动呈现 (Priority: P2)

用户做出主题选择后，不希望每次打开应用都重新设置：应用应记住其选择，下次启动直接以所选主题呈现。对首次使用（尚无任何偏好记录）的用户，应用以默认的 light 主题呈现；即使偏好数据缺失或损坏，应用也必须能正常启动。

**Why this priority**: 记忆是"选择一次、长期受益"的关键；若每次启动都被重置，主题功能价值大打折扣。它依赖 US1 的切换能力，但可独立验证（持久化与启动行为）。

**Independent Test**: 切换至 dark → 完全退出应用 → 重新启动 → 应用直接以 dark 呈现（含启动首屏）；清除偏好数据后重启，应用回到 light 默认且正常运行。

**Acceptance Scenarios**:

1. **Given** 用户已选择 dark 主题，**When** 退出并重新启动应用，**Then** 应用从首屏开始即呈现 dark，无需用户再次操作。
2. **Given** 应用全新安装且无任何主题偏好记录，**When** 用户首次启动，**Then** 应用以 light 主题呈现。
3. **Given** 已保存的主题偏好数据缺失或损坏，**When** 应用启动，**Then** 应用以 light 主题正常启动，不报错、不崩溃。
4. **Given** 用户已选择主题，**When** 应用启动并显示界面，**Then** 首屏直接为目标主题，过程中无可感知的"先浅后深"（或相反）的闪变。

---

### User Story 3 - 双主题下的完整适配与内容保真 (Priority: P3)

两种主题必须覆盖应用的全部界面，同时不得干扰业务内容的"真实面貌"：营销邮件/短信的预览与测试发送内容在任何主题下都应呈现收件人实际会看到的样子（典型浅色邮件观感），而不是被深色主题反色；用户上传的图片与外部抓取的网页素材也不应被主题处理。整套界面在两种主题下均保持可读：文字与背景对比度达标，状态标识、图谱与图表可辨。

**Why this priority**: 覆盖面与保真是"从能切换、到放心用"的质量门槛：营销内容的预览若被主题污染，用户会误判群发效果——群发是本产品的高风险副作用之一。它建立在 US1/US2 之上，可作为质量审计独立验收。

**Independent Test**: 以覆盖全部页面的检查清单，在 light 与 dark 两种主题下逐项走查（含图谱可视化、表格、图表、弹窗、空态、引导提示、滚动条等），确认适配缺陷为 0；抽查若干营销内容模板，确认两种主题下预览与测试发送内容一致且为收件人视角。

**Acceptance Scenarios**:

1. **Given** 应用处于 dark 主题，**When** 用户打开营销内容预览，**Then** 预览区以收件人视角呈现内容（浅色基底、原样配色与排版），不被主题反色或加滤镜；测试发送给自己收到的内容与预览一致。
2. **Given** 用户上传或抓取获得的图片素材，**When** 在任一主题下查看，**Then** 图片保持原始色彩，不被反色处理。
3. **Given** 存在图谱可视化、数据表格与图表等数据密集界面，**When** 在两种主题下查看，**Then** 节点、连线、文字标注与数据均可读、可区分，无"深色下看不清"的区域。
4. **Given** 任一可达页面与瞬时界面（下拉菜单、悬浮提示、确认弹窗、滚动条），**When** 在两种主题下走查，**Then** 不存在未适配区域（例如深色下仍突兀的浅色板块、看不清的文字）。

---

### Edge Cases

- **首次启动且无偏好数据**：以 light 呈现（默认），不出现空白界面或错误主题。
- **偏好数据损坏或不可读**：回退 light 并正常运行，不阻断启动流程。
- **切换时存在进行中的操作**：未保存的表单输入、进行中任务界面状态不丢失、不中断（切换为纯展示层行为）。
- **瞬时与叠加界面**：下拉菜单、悬浮提示、对话框、遮罩层、滚动条、通知/提示条在两种主题下均清晰可辨。
- **用户生成内容**：用户上传的图片、外部网页抓取素材、品牌 Logo 等不被主题反色或调色。
- **数据迁移**：应用设置备份/恢复到另一设备后，主题偏好随设置一并保留；若目标环境无偏好数据则回退 light。
- **深色下的状态色彩**：成功/失败/警告等状态标识在两种主题下均可区分，不因底色变深而失去可辨性。
- **长列表与虚拟滚动区域**：深色主题下滚动、悬停行高亮仍然可见。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 应用 MUST 提供 light 与 dark 两种主题模式，用户 MUST 能手动切换；两种模式 MUST 覆盖应用全部界面。
- **FR-002**: 应用 MUST 在主界面所有页面提供全局可达的主题切换控件，一步完成操作，且控件 MUST 明确指示当前所处的主题模式。
- **FR-003**: 主题切换 MUST 即时全局生效——无需重启或刷新；已打开的弹窗、提示等叠加界面 MUST 同步切换。
- **FR-004**: 主题切换 MUST NOT 丢失或重置用户当前的操作状态（未保存的表单输入、进行中任务的界面状态）。
- **FR-005**: 应用 MUST 记忆用户的主题选择；退出重启后 MUST 以所选主题呈现。
- **FR-006**: 首次启动或无有效偏好记录时，应用 MUST 以 light 主题呈现；偏好数据损坏 MUST NOT 阻断应用启动。
- **FR-007**: 应用启动时 MUST 直接以目标主题渲染首屏，MUST NOT 出现可感知的"先浅后深/先深后浅"闪变。
- **FR-008**: 两种主题下全部界面元素（含表格、图谱可视化、图表、状态标签、弹窗、空态与引导、滚动条）MUST 完整适配，不存在未适配或不可读区域。
- **FR-009**: 两种主题下正文文本与背景的对比度 MUST 不低于 4.5:1；状态标识（成功/失败/警告等）在两种主题下 MUST 可辨别。
- **FR-010**: 主题 MUST NOT 改变业务内容的呈现保真：营销内容预览与测试发送内容在任何主题下 MUST 保持收件人视角（原样配色与排版）。
- **FR-011**: 主题 MUST NOT 对用户生成内容（上传图片、抓取素材等）进行反色或调色处理。
- **FR-012**: 主题偏好 MUST 视为用户设置数据的一部分，随设置的备份/恢复与迁移一并保留。
- **FR-013**: 除主题偏好本身外，切换主题 MUST NOT 修改任何业务数据、MUST NOT 触发任何对外调用（大模型/发送/抓取）——切换为纯本地展示层行为。

### Key Entities *(include if feature involves data)*

- **主题偏好（Theme Preference）**：记录用户当前选择的主题模式。取值：light / dark；默认值：light（无记录或记录无效时）；持久化范围：随应用"设置"数据保存与迁移（复用既有设置备份/恢复能力），为单用户、设备级偏好，不跨设备云同步。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户可在任意主页面以 1 步操作完成主题切换；切换后全部可见界面在 1 秒内完成整体呈现切换。
- **SC-002**: 以覆盖全部可达页面与常见交互界面的检查清单在两种主题下走查，未适配、不可读或被主题误处理（反色/调色）的缺陷数为 0。
- **SC-003**: 两种主题下正文文本与背景对比度均 ≥ 4.5:1，检测不达标项为 0。
- **SC-004**: 在"切换后退出并重启"的验证中，100% 场景下应用以用户所选主题启动；全新环境 100% 以 light 默认启动。
- **SC-005**: 启动过程中可感知的主题闪变次数为 0（以启动过程录屏/截帧复核）。
- **SC-006**: 主题切换不造成任何未保存输入丢失（切换场景测试中数据丢失次数为 0）。
- **SC-007**: 抽查不少于 5 个营销内容模板，两种主题下预览与测试发送内容的渲染差异项为 0。

## Assumptions

- 用户明确要求"两种模式"：v1 仅提供 light 与 dark 手动切换，不包含"跟随系统外观"的自动模式（如需可作为后续版本增补）。
- 默认主题为 light：与当前应用既有浅色观感一致，保证既有用户体验连续。
- 主题偏好是设备级、单用户本地偏好，不做跨设备云同步；但随本机"设置"数据的备份/恢复与迁移一并保留（与 001 设置迁移能力一致）。
- 深色主题采用行业通行的"深色背景 + 浅色文字"观感，追求可读性与整体一致性，不追求与特定商业产品完全相同的色值。
- 主题切换是纯展示层行为：不触发业务数据变更、对外调用或后台任务（见 FR-013）。
- 内容保真优先于主题一致性：营销内容预览始终代表收件人实际看到的渲染效果，这是对"群发副作用风险"的既定产品约束（与 001 营销内容模块一致）。
- 主题切换入口位置不限定具体页面区域，但必须满足"全局可达、一步操作、当前模式可辨识"（见 FR-002）。
