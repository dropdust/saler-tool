# 销售获客工具 · 用户手册（初稿）

> 面向使用者的第一版说明：安装 → 首次配置 → 五个模块的操作路径 → 密钥与合规 → 常见问题。
> 对应快速验收场景见 `specs/001-sales-tool/quickstart.md`（S1–S12）。

## 1. 这是什么

本地优先（数据留在你自己电脑上）的销售获客工作台，覆盖从**种子知识库 → 线索挖掘 → 多语内容 → 自有通道 → 批量触达**的完整闭环：

| 模块 | 你在这里做什么 |
|---|---|
| 种子知识库 | 建模目标画像（产品线/客户角色/市场），维护搜索种子；可用大模型扩充、翻译与审核 |
| 客户线索 | 按种子检索公开网页，抓取并抽取邮箱/电话/WhatsApp 等联系方式，导入导出 |
| 营销内容 | 中文母版为源，AI 辅助起草与多语言生成；版本化与"先审后发"发布门 |
| 营销通道 | 登记你自有的发信邮箱/短信网关，连通测试、限额与用量、试发 |
| 营销计划 | 圈人群 × 选内容 × 选通道，预估→试发→启动；实时进度、台账与报表、退订黑名单 |

## 2. 安装

### Windows 10/11
下载 `SalerTool-Setup-<版本>.exe` 运行安装（WebView2 系统自带）。

### macOS 12+
下载 `SalerTool-<版本>-arm64.dmg`，拖入"应用程序"。首次打开若被 Gatekeeper 拦截，右键 →「打开」。

### Ubuntu 22.04+（Linux）
- 先安装运行库：`sudo apt install python3-gi gir1.2-webkit2-4.1`
- 下载 `SalerTool-<版本>-x86_64.AppImage`：`chmod +x` 后直接运行。
- 由包管理器安装的 WebKitGTK 版本过低（< 2.36）会导致窗口打不开；应用会给出明确提示。

### 开发模式（源码运行）
```bash
cd backend && uv sync --extra dev && uv run python -m saler.desktop
```

## 3. 首次配置（约 5 分钟）

1. **数据目录**：设置 → 通用设置。默认在用户数据目录（Win `%LOCALAPPDATA%\Saler`、macOS `~/Library/Application Support/Saler`、Linux `~/.local/share/Saler`）。可迁移到其他磁盘；迁移=校验→复制→原子切换。
2. **大模型服务（可选）**：设置 → 大模型服务 → 添加（如 DeepSeek/Qwen/Kimi/本地 Ollama），粘贴 API 密钥 → 测试。未配置也能全部手工使用，AI 入口会提示"先配置模型"。
3. **检索渠道（做挖掘前必配）**：设置 → 检索渠道 → 添加（推荐 Serper，注册最简）→ 测试。多渠道路径按优先级自动故障转移。
4. **发送通道（做触达前必配）**：营销通道 → 添加：
   - 邮箱：SMTP 服务器/端口/加密方式/账号 + **授权码**（多数邮箱不是登录密码）；
   - 短信：选择模板（Twilio/通用 HTTP）并填入网关凭证。
   添加后点「测试」，再「试发 1 封给自己」。

## 4. 五步闭环操作路径

```
① 种子知识库：图谱管理建节点 → 种子列表加搜索词（或 AI 扩充/检索扩充）→ 待审核采纳
② 客户线索：挖掘任务选种子范围启动 → 候选域名页查看 → 客户列表修订联系方式/标记排除
③ 营销内容：新建主题 → AI 起草母版或手工撰写（{{company_name}} 等变量）→ 发布
④ 营销通道：见上，测试+试发
⑤ 营销计划：新建计划向导（人群→内容→通道→节奏）→ 预估确认 → 试发 2 封 → 启动 → 台账/报表
```

要点速记：

- **先审后发**：AI 产出（图谱/种子/内容）与手工内容一样，必须审核/发布后才会进入执行链路。
- **防重复打扰**：客户默认只联系一次；新计划会自动跳过已触达客户（可在人群设置中显式允许重发）。
- **退订即全局生效**：设置 → 退订黑名单加入的对象，在所有计划（含进行中）发送前自动拦截。
- **断点续跑**：挖掘与发送都支持暂停/中止后从上次位置继续，不重发已成功记录。

## 5. 知识点详解

### 5.1 种子知识库与图谱（重点）

#### 5.1.1 图谱是什么，解决什么问题

把"我卖什么（产品线）、卖给谁（客户角色）、卖到哪里（市场/国家）、具体买方是谁（机构实体）"用节点与关系组织成一张知识图谱，再由这张图生成**爬虫种子**（结构化搜索词）——种子才是挖掘任务的真正输入。图谱是"通用化"的关键：换行业只需重建图谱，工具本身不用换。

| 节点类型 | 回答的问题 | 示例 | 说明 |
|---|---|---|---|
| 产品线 | 我卖什么 | 电力金具、光伏支架 | 种子的分类维度之一 |
| 客户角色 | 谁采购 | EPC 总包、进口商、电气经销商 | 种子的分类维度之一（买方画像） |
| 市场/国家 | 卖到哪里 | 肯尼亚、沙特 | 可另填"大区"（如东非/中东） |
| 机构实体 | 具体买方是谁 | 某国电网公司、某经销商、某展会 | 多由 AI/检索扩充产出；具名实体的种子通常产出最高 |

> 业务经验：**直接列举具名买方实体**（如"XX 电网公司 联系方式"）的种子，产出远好于"产品词 × 泛角色词"的泛搜。图谱里的机构实体越多、越准，线索质量越高。

#### 5.1.2 词表：节点的多语言别名

每个节点可以维护一张词表，条目含**语言（17 种：英/中/俄/阿/西/葡/法/德/意/波/土/越/泰/印尼/印地/波斯/乌克兰）+ 类型（名称/别名/同义词/术语）**。用途：

- 生成多语言搜索词（同一概念在各语言下的说法）；
- AI 翻译时作为术语表复用——你维护的术语会被优先采用，保证产品名、行业术语在各语言版本中保持一致。

AI 产生的词条默认"待审核"，在「图谱管理 → 词表」里逐条采纳/拒绝。

#### 5.1.3 关系（4 类）

| 关系 | 含义 |
|---|---|
| 产品线 × 客户角色（适配） | 这条产品线面向这类买方 |
| 产品重点市场 | 这条产品线的重点国家/地区 |
| 机构归属市场 | 这家机构实体位于/属于某市场 |
| 机构属于客户角色 | 这家机构实体属于某类买方 |

关系在「图谱管理 → 关系」标签页手工新建（可删除），检索扩充时会自动产出"机构归属市场"关系。关系会显示在**图谱视图**上，帮助你（和 AI 扩充）理解业务结构——例如"产品线-角色-市场"的连线越完整，说明打法描述得越清楚。

#### 5.1.4 来源与审核（先审后发）

| 来源 | 默认审核状态 |
|---|---|
| 手工、导入 | 已采纳（可直接使用） |
| 大模型、检索 | **待审核**（必须人工采纳后才进入执行队列） |

- 种子审核在「待审核」页（支持逐条/勾选/本页全部采纳）；节点与词表审核在「图谱管理」页。
- 挖掘任务默认只跑"已采纳且待执行"的种子——**未审核的 AI/检索产出不会被执行**。
- 状态：待执行 → 执行中 → 已完成；不再需要的种子置为"已失效"（保留产量历史，不物理删除）。

#### 5.1.5 怎么建图谱（操作路径）

1. **图谱管理 → 新建节点**：先建 3–5 条产品线、客户角色、市场（市场可填大区）。
2. 对每个节点点「词表」，补充该概念在各语言的名称/别名（做外贸市场时至少补英文与当地语言）。
3. （可选）「新建关系」把产品线连到客户角色、把重点市场连到产品线。
4. **种子列表 → 新建种子**：搜索词 + 分类（产品线/客户角色/市场）+ 语言 + 优先级（高/中/低）+ 批次（建议按来源/日期分组，如 manual-1）。
5. 重复的节点用「合并」（保留目标节点，词表/关系/种子引用自动转移后删除来源节点，仅限同类型合并）；不再使用的节点用「停用」（从图谱视图与各选择器中消失，历史数据不受影响）。

#### 5.1.6 三种扩充方式

| 方式 | 入口 | 输入 | 产出 |
|---|---|---|---|
| 手工 | 种子列表 → 新建种子 | 你自己写的搜索词 | 直接入库（已采纳） |
| AI 扩充 | 种子列表 → AI 扩充 | 行业/业务描述（可选参考节点、数量 5–200，默认 20） | 候选节点、关系、**中文母版**种子（批次 `llm-YYYYMMDD`），全部待审核 |
| 检索扩充 | 种子库 → 导入与回灌 → 检索扩充图谱 | 每行一个检索关键词；可选关联市场节点；每词结果数/实体/种子上限 | 候选机构实体（org，带来源页 URL）、"机构归属市场"关系、种子，全部待审核 |

**AI 扩充的工作链路（重要）**：

1. 产出**一律是中文母版**（语言不由模型决定），且全部进入"待审核"；库中已存在的节点/搜索词会自动跳过；
2. 在「待审核」页采纳种子、在「图谱管理」页采纳节点/词表；
3. 采纳后回到种子列表，**勾选中文种子 → 「翻译选中」→ 选目标语言（可多选）**，产出各语言的待审核种子（批次 `llm-tr-<语言>-<日期>`，备注注明"译自种子 #N"）；翻译会复用你词表里的术语；
4. 翻译结果再次审核采纳后，才能被挖掘任务执行。

> 调用前提示：AI 扩充会把"业务描述 + 参考节点名称"发送到你配置的大模型服务；除此之外的数据不出本机。

**检索扩充的提炼规则**：只保留标题中含组织特征词（Ltd/Corp/GmbH/Electrical/Trading…）的结果，剔除社交、电商、目录类通用域名与列表/导购页；每条候选都带来源 URL 供人工核对（置信度统一标 0.5）。种子的两个来源：① 每个候选机构的 `"机构名" contact` 检索；② 你输入的关键词本身。

#### 5.1.7 图谱视图怎么用（识别空白市场）

进入「种子库 → 图谱视图」：

- **两个视图**：结构视图（产品线-客户角色-市场，看"打法"覆盖）；实体视图（机构实体-市场，看具体买方的分布）。
- **颜色四态**（图例在图上）：绿＝已产出联系方式；黄＝已执行但无联系方式；蓝＝已建种子·待执行；灰＝**空白（无种子）**——灰色节点就是你的下一个市场机会。
- **节点大小**＝种子数与联系产量的综合（越大产出越多）；**拖拽**调布局、**滚轮**缩放。
- **边**：由种子自动推导的"共现"关系画实线（产品线×角色、角色×市场同时出现，粗细≈共现种子数）；你手工建立的显式关系画虚线。
- **批次筛选**：只看某个批次（如 `llm-20261013`）的覆盖情况；**搜索框**输入名称子串即定位（自动高亮并居中；命中另一视图的节点会自动切换视图）。
- **点击节点**：查看该节点的种子数（已完成数）、候选公司数、联系方式数；「查看该节点种子」跳到种子列表（市场节点会自动带上筛选）。

#### 5.1.8 产量与统计

- **候选公司**＝该种子命中的不同域名数；**联系方式**＝这些域名下抽到的不同联系方式数。注意：同一域名被多条种子命中会分别计数，统计页总量是"按条归因、含重复"的口径，与客户列表的去重总数不同。
- 「种子库 → 产量统计」：按**批次/产品线/客户角色/市场**分组看谁在产出；"产出密度"条反映相对产量；**零产出种子**（已执行但没抓到联系方式）单列，建议复核翻译或置为失效。
- 种子列表支持按"产量"排序，快速找出高产出种子并提高其优先级。

#### 5.1.9 导入、导出与外部回灌

- **批量导入种子**（导入与回灌页）：每行一条搜索词；也支持粘贴 csv（`query,lang,priority,batch`）；默认语言 en、优先级中、批次 `import`；重复的搜索词自动跳过（种子按搜索词唯一）。
- **导出执行清单**：txt（逐行，供外部工具/人工执行）或 csv（含分类/优先级等元数据）；可按批次、审核范围（仅已采纳/含待审核）、优先级 ≤、条数上限筛选；文件写入数据目录的 `exports/`，界面显示路径可点击复制。
- **回灌外部收割结果**（harvest_v1）：适合"导出清单 → 外部渠道执行 → 结果回灌"的工作方式。每行一条 JSON（`seed_query` + `results[{url,title,snippet}]`）或 csv（`query,url[,title,snippet]`）；命中的种子自动转"已完成"并重算产量，新域名进入待抓取队列；未匹配的查询会列在报告里（最多 100 条）而不是丢失。

### 5.2 客户线索（爬虫）

#### 5.2.1 挖掘是怎么跑的（两个阶段）

```
阶段 1  种子 → 检索渠道 → 候选域名（记录来源与命中的种子，按域名去重）
阶段 2  候选域名 → 抓取公开网页 → 抽取联系方式 → 客户/联系方式入库
```

任务状态**全部存在本地数据库**：中途退出、断网或取消后再启动，只处理未完成部分——已完成的目标不会重复抓取。

#### 5.2.2 检索渠道：整个链路的数据源头

| 接入方式 | 代表渠道 | 特点 |
|---|---|---|
| 官方 API | Serper（注册最简）、Brave、Tavily | 稳定、需密钥；添加界面一键直达官方申请页 |
| 网页解析（免密钥） | Bing、Wikipedia、百度、Mojeek、DuckDuckGo、Google | 无需注册；受服务商风控影响（限流/验证码/软封禁），**失败自动切换下一渠道、异常页面绝不写入数据**；合规责任自担 |

- **优先级与故障转移**：按优先级数字升序调用；某渠道失败自动切到下一个，任务不中断。全部渠道都不可用时任务暂停并提示。
- **健康与用量**：每个渠道显示健康（正常/异常/未测）、最近一次失败的原因分类（限流/风控封禁/解析失败/网络/密钥/额度）、今日用量（按日重置）。失败原因帮你决定处置：限流→稍后再试；风控封禁→换渠道；网络→检查代理。
- **幌子结果防护**：网页渠道在风控下可能返回"幌子页"（页面正常、条目却与查询毫不相关）；系统按词面相关性识别，直接判该渠道受阻——不写入任何数据、失败自动切换下一渠道。
- **市场定位建议**：中文市场加**百度**；机构资料佐证用 **Wikipedia**；独立索引补充用 **Mojeek**；全球覆盖靠 Google/Bing；隐私场景用 DuckDuckGo。初次使用建议先配 1 个官方 API（Serper）保底，再补免密钥渠道兜底。

#### 5.2.3 启动挖掘任务

「客户线索 → 挖掘任务 → 启动挖掘」：

- **种子范围**：全部待执行（已采纳）／指定种子（下拉只列已采纳、待执行的种子）。
- **配置项**：并发（1–10，默认 5）、单站间隔（≥0.2 秒，默认 1 秒）、单站页数（1–20，默认 6）、是否遵循 robots.txt（默认遵循）、网络代理（留空沿用全局设置）。
- **监控**：进度条分两段（检索 N/M 条种子 → 抓取 N/M 个域名），下方是实时日志；运行中可**暂停/恢复/取消**。
- 提醒：没有启用任何检索渠道时无法启动（会提示先去「设置 → 检索渠道」添加）；每次任务会把库中所有"待抓取"的域名一并处理，包括之前任务遗留的。

#### 5.2.4 抓取与抽取的知识点

- 每个域名抓**首页 + 同站联系页**（href 或锚文本含 contact/kontakt/联系 等），不超过"单站页数"；单站最小间隔限速、网络类错误自动重试 1 次、robots.txt 默认遵守。
- 抽取范围：**邮箱、电话、WhatsApp**（wa.me / api.whatsapp 链接）、**Facebook、LinkedIn、X、Instagram、微信**。
- **反混淆与清洗**：优先采集 `mailto:`/`tel:` 链接；自动还原 `(at)`/`(dot)`、零宽字符、JS 字符串拼接的邮箱；剔除图片伪邮箱（logo@2x.png）、noreply 类角色地址；占位域名标为"疑似无效"（保留供人工复核，不误删）。
- **分类与去重**：邮箱按用途自动分类——采购/销售/通用/其他（如 purchase@→采购）；**同公司同类型同值只保留一条**（多个页面出现也算一条）。
- **国家/语言**：域名 ccTLD 推断国家（如 .ke→肯尼亚），页面 `html lang` 推断使用语言——后续营销计划的"按客户语言匹配内容"就依赖它。

#### 5.2.5 候选域名与客户

- **域名状态**：待抓取 → 已抓取（有联系方式）/ 无联系方式 / 失败（重试 2 次仍失败）；"页/次"列＝抓取页数/尝试次数。
- **检索溯源**：列表"命中"列＝该域名被多少条检索词命中；点击数字查看明细（query 词、任务、首次命中时间）。排查异常域名（如酒店/旅游等不可能出现在你产品目录里的站点）先看这里；客户导入来源没有检索命中记录（显示 —）。
- 抓取成功后按域名**归并**成客户（公司名取网页标题）；一个域名对应一家客户，同一家公司出现在多个域名时，在客户列表勾选后用「合并选中」合并（域名与联系方式转移并去重；数据量大时可开"大列表模式"虚拟滚动，多选合并请先切回标准模式）。
- **客户状态**：新线索 → 已联系 → 已回复 → 已成交 / 未成交 / 无效。标记"已回复/已成交/未成交/无效"会**立即停止**该客户所有待发消息（台账记为"跳过"，不会误发），并从后续跟进轮次与人群圈选中排除。
- **客户详情**：修订名称/状态/标签（回车创建）/备注；补录/删除联系方式、修改分类与有效性——人工修订结果会直接作用于发送与排除判断。

#### 5.2.6 排除规则（过滤同行、供应商与无关站点）

- 三类规则：**关键词**（匹配标题/摘要/域名）、**域名**（精确或子域匹配）、**名单**（每行一条，关键词与域名混合）。
- 可在域名列表逐条"排除/恢复"，也可新建规则后点「**对存量重跑**」统一评估已有域名（报告：评估 N 个、新排除 M 个）。
- 被排除对象**移出买家列表单独存放**（不删除、不再抓取、不进入营销人群），随时可恢复。

#### 5.2.7 导入与导出

- **导入既有名单**：本机 `.csv/.xlsx` 文件（绝对路径）或粘贴 CSV，列：`email,phone,company_name,domain,country,language,tags,note`；报告会列出新增公司/并入已有/新增联系方式/重复跳过/**黑名单命中**/错误行。
- **导出买家列表**：CSV 或 Excel（Excel 版另含"被排除""统计"两个 Sheet）；可按状态、国家筛选——被排除对象不会混进买家主表。

### 5.3 营销内容

#### 5.3.1 内容的三层结构

```
主题（一类要发的内容，如"电力金具-肯尼亚-首轮"）
 └─ 语言版本（同一主题的多个语言变体，如 中文母版 / 英文 / 俄文）
     └─ 版本（v1、v2…每次保存生成新版本，完整审计链）
```

- 主题：名称（唯一）、类型（**邮件/短信/社媒消息**；v1 实际可发送的是邮件与短信，社媒为二期）、母版语言（默认中文）、备注。
- 语言版本：一个主题每种语言只有一个版本；发送时按客户语言自动匹配的就是它。
- 版本：每次保存都产生新版本（"保存即生成新版本"），记录时间、创建者（用户/AI）与变更说明。

#### 5.3.2 变量占位符（7 个内置变量）

语法 `{{变量名}}`（大小写不敏感）。发送时按客户/通道数据逐一代入：

| 变量 | 发送时取值 |
|---|---|
| `{{company_name}}` | 客户公司名 |
| `{{country}}` | 客户国家 |
| `{{language}}` | 实际采用的语言（含回退后的语言） |
| `{{sender_name}}` | 通道的发件人名称 |
| `{{signature}}` | 通道的签名 |
| `{{today}}` | 发送当天日期 |
| `{{contact_name}}` | 联系人姓名（**当前版本尚未自动代入**，会渲染为空——预览与台账会提示） |

编辑器正文上方有变量按钮，点击即在光标处插入。**预览会提示缺失变量**（渲染为空并给出告警，不阻断发布）。

#### 5.3.3 推荐工作流（母版 → 多语言 → 审校 → 发布）

1. **新建主题**：内容页 → 新建主题（名称 + 类型 + 母版语言）。
2. **AI 起草母版**（可跳过、纯手工写）：展开主题 → 「AI 起草」→ 填业务要点（可选语气）→ 产出为**新草稿版本**（来源标"AI 辅助编写"，需人工审核）；调用前会提示"业务要点将发送给大模型服务"。
3. **预览**：编辑页右侧预览卡片——手工填示例值，或直接选一个真实客户带入其公司名/国家/语言；邮件类型才会渲染主题行。
4. **多语言生成**：主题展开行 → 「多语言生成」→ 选目标语言（可多选，母版语言除外）→ 以母版当前版本为源翻译；**复用图谱词表术语**保持译法一致，`{{变量}}` 原样保留；已存在同语言版本时会被**覆盖为新版本**。产出同样是草稿。
5. **人工审校 → 发布**：发布后该语言版本才会出现在营销计划的可选清单里（先审后发）。
6. **迭代与回溯**：保存即新版本；「版本历史」可查看任意历史版本并**恢复**（恢复 = 以旧内容创建一个新版本，历史不受影响）。注意：**修改一个已发布的版本会自动退回草稿**，需重新发布后计划才能选用。

#### 5.3.4 发布门与状态

- 状态：**草稿 → 已发布**（可"归档"移出可选清单；需要时可重新发布）。
- 发布校验：当前版本的主题行与正文不能同时为空。
- **计划只能选用"已发布"的主题**——创建计划时下拉里只会出现已发布内容；若无已发布内容，向导会明确提示先去发布。
- 发送台账会记录每条消息实际使用的**内容版本号与语言**，可追溯"这位客户收到的是哪一版、是否语言回退"。
- 删除主题会连同其语言版本与全部版本历史一起删除（不可恢复）；已被营销计划引用的主题受引用保护，无法直接删除。

### 5.4 营销通道

#### 5.4.1 支持哪些通道

- **邮件（P0，第一优先级）**：SMTP 自有发信服务器（QQ/163/企业邮箱/Gmail 等）。
- **短信**：HTTP 短信网关，预置两个模板——**Twilio（国际）**与**通用 HTTP 网关**（自建网关/其他服务商）。
- **社媒（WhatsApp/Facebook 等）**：v1 不发送，只做联系方式抽取、展示与导出（人工跟进）；通道类型下拉中"社媒"为二期预留、不可选。

#### 5.4.2 添加通道（字段速查）

**邮件（SMTP）**：

| 字段 | 说明 |
|---|---|
| SMTP 服务器 / 端口 | 如 `smtp.qq.com`；端口默认 465 |
| 加密方式 | `ssl`（默认）/ `starttls` / `plain` |
| 登录账号 | 你的邮箱账号 |
| 授权码/密码 | **多数邮箱需用「授权码」而非登录密码**；加密存储、不回显；编辑时留空=保持原密钥 |
| 发件人名称 / 发件地址 / 回复地址 | 发件身份；回复地址留空则同发件地址 |
| 签名 | 落款，同时是内容变量 `{{signature}}` 的取值来源 |
| 服务商建议日上限（可选） | 仅作记录，不参与节流；实际的量以"发送限制"为准 |

**短信（HTTP 网关）**：选择模板后自动带出推荐配置——网关地址、请求方法、认证方式（Bearer/Basic）、账号与密钥、字段映射（号码字段/正文字段/签名字段/消息 ID 字段）；**签名**需按服务商要求报备。

**发送限制（两类通道通用）**：每日上限（默认 200，**0 = 不限**）、条/分钟（默认 20）、并发数（当前版本为预留展示字段，实际节流按"条/分钟"执行）。

#### 5.4.3 测试与试发（两回事）

- **「测试」**：验证配置是否可用。邮件＝真实连接并登录 SMTP 服务器；短信＝真实请求一次网关验证连通与凭证。结果与失败原因显示在列表上方；健康状态：**正常/异常/未测**。
- **「试发」**：用**内置样例文案**发到**你指定**的收件地址（邮件填邮箱、短信填手机号）——只验证"发得出去"，不消耗每日额度、不写台账。建议新通道配置后先测试再试发 1 封给自己。

#### 5.4.4 用量与节流

- 每个通道**独立记账**：今日已发/每日上限、累计发送（列表与「用量」弹窗可见）。
- **每日额度按 UTC 零点重置**（北京时间上午 8 点）；额度恢复后**重新点「启动」**即可续发剩余记录——应用不会在后台自动重发。
- 发送节流：同一通道两条消息之间有最小间隔（20 条/分钟 ≈ 每 3 秒一条），并由"每日上限"封顶。
- 多个同类型通道可并存（多个发件邮箱、多个短信网关），各自限量独立核算；营销计划中按选择顺序使用"主通道 + 备用通道"。

#### 5.4.5 启停与删除

- 「启用」开关控制通道是否可被计划选用；**停用的通道不会出现在计划的通道选择中**。
- 删除通道：该通道未被任何计划/台账引用时可直接删除；**已被引用的通道可能删除失败——建议用「停用」代替删除**（历史台账始终不受影响）。

### 5.5 营销计划

#### 5.5.1 创建向导（5 步）

1. **人群**：按国家、语言、公司状态（多选，默认勾选"新客户 + 已触达"——即客户列表中的"已联系"）、标签圈选，可设目标数量上限；"允许重发"默认关闭。
   - 硬性排除：已排除客户、已回复/已成交/未成交/无效客户、退订对象**一律不进人群**；
   - 每家公司自动挑 **1 个最佳联系方式**：邮件计划取邮箱、短信计划取电话；优先级 采购 > 销售 > 通用 > 其他；无效与已退订的会被剔除。
2. **内容与语言**：内容主题**只能选已发布的内容**；语言策略选"自动匹配客户语言"或"固定语言"；「缺失回退语言」默认 en——客户语言没有对应版本时用回退语言发送，并在台账标"回退"。（回退以本向导设置为准。）
3. **通道**：多选，**选择顺序即优先级**——第一个是主通道，其余作为失败自动切换的备用通道。
4. **节奏**：「立即开始（确认后启动）」；定时发送为后续版本（暂不可选）。可设"每日计划上限"（0 = 不限），防止一天发太多。
5. **预估确认**：展示**覆盖客户数、消息条数、预计时长、语言分布、回退标注、将被排除（退订/已触达）**——确认后「创建并启动」。

> 提示：每家公司只发一条（一人一条），消息条数≈覆盖客户数；多轮跟进是另外的轮次机制（见 5.5.5）。

#### 5.5.2 试发（启动前的安全阀）

计划监控页「**试发 2 封**」：用**人群里前 2 位客户的真实内容**渲染，发到主通道的发件地址（即你自己的邮箱，需已在主通道填写"发件地址"）；**不写台账、不占计划额度**，与正式启动完全独立——建议每次启动前先试发确认排版与链接。

#### 5.5.3 执行与监控

- 计划状态：**草稿 / 执行中 / 已暂停 / 已完成 / 已取消**。操作：启动、暂停、恢复、中止（中止后不可再启动，未发记录保留在台账备查）、删除（执行中的计划需先中止才能删除）。
- 监控页实时显示：**已发 / 失败 / 退信 / 跳过 / 排除 / 剩余**，以及最近任务日志。
- **中断即断点**：通道额度用尽、网络中断或你手动暂停/中止时，**剩余记录保持"待发"**（不算失败、不会丢失），问题排除后重新点「启动」从断点续发；已发出的不会重发。
- **失败自动处理**：限流/超时/网络/服务端等瞬时错误会在同一通道自动重试（最多 3 次）；认证或额度类错误**直接切换到备用通道**；收件人被拒（如地址不存在）判为"退信"、不重试。失败/退信可在台账勾选后「重试失败项」。
- 每成功发送一条，该客户状态会自动从"新线索"推进为"已联系"。

#### 5.5.4 防重复打扰与发送台账

- **同一客户同一轮次只发一次**；跨计划**默认跳过已触达客户**——新计划不会重复打扰（如确需再发，在向导第 1 步打开"允许重发"；退订对象则始终拦截）。
- 被跳过/排除的记录会注明原因：已触达、退订/抑制、公司已回复/已成交等（台账中悬停"?"可看）。
- **台账记录每一条消息的全貌**：轮次、客户、联系方式（发送时快照）、通道、语言（回退标黄）、状态、失败原因、发送时间、**内容版本号**（发送时冻结，事后改内容不影响已发记录）。
- 台账状态对照：`pending` 待发送、`sent` 已发送、`failed` 失败、`bounced` 退信、`skipped` 跳过、`suppressed` 已排除（状态列可能直接显示上述英文码）。
- **导出**：报表页「导出台账（XLSX）」→ 含"统计"（按通道/语言/轮次分组）与"台账"（逐条明细）两个 Sheet，文件写入数据目录 `exports/`。

#### 5.5.5 多轮跟进（当前版本说明）

- 第 1 轮在创建计划时自动建立；后续轮次的设计语义是：**上一轮已发送、且未标记"已回复/已成交/未成交/无效"、未退订、仍有可用联系方式**的客户进入下一轮。
- 当前版本的界面**尚未提供"新增轮次/启动跟进轮"入口**（间隔天数也不会自动触发），多轮跟进能力将在后续版本开放——本节规则供你了解其工作方式。

#### 5.5.6 退订 / 黑名单

设置 →「退订黑名单」，对象支持**邮箱 / 电话 / 域名**（界面可建；联系人与客户维度的条目由其他链路写入并在列表可见），原因：主动退订（默认）/ 退信 / 投诉 / 手动 / 无效地址。

- **即时生效**：命中对象不再进入任何后续计划的人群；**进行中的计划也会在每条发送前二次校验并自动跳过**——加入退订后无需重跑计划。
- 邮箱与域名不区分大小写；导入客户名单时命中黑名单的联系方式会被标记。
- 移除后该对象可重新进入人群，但已记为"已排除"的历史台账记录不会回滚。
- **注意：退信不会自动加入黑名单**——收到退信时请手动登记一条（原因选"退信"），避免继续打扰。

### 5.6 AI 调用明细（排障用）

每次 AI 调用（扩充 / 翻译 / 起草）**实际发给大模型的内容**与**模型的原始返回**都保存在本机，可随时回看：

- **入口一（任务中心）**：顶栏「任务」→ 任意 AI 任务的卡片 →「调用明细」（已完成的、失败的都能看，失败时最有用）；
- **入口二（扩充对话框）**：种子列表 →「AI 扩充」→ 任务结束后页脚出现「查看调用明细」。

明细按"一次调用"成卡片，修复重试（输出未通过校验时的自动纠错）合并为同一张卡、逐次尝试分列展示：

- **入参**：实际发送的消息原文（即各功能"调用前提示"里承诺发送的范围）；纠错重试会追加"模型上次输出 + 纠错要求"，一并可见；
- **出参**：模型原始返回（未解析的 JSON 文本）；每次尝试的**耗时**与 **token 用量**；多语言翻译任务按语言标注每次调用；
- **失败原因**：错误类别与详情原文（如超时、鉴权失败、输出格式不符、服务端响应异常）；
- **进行中（请求已发出、还在等模型返回）**：请求一发出就有记录，标签显示「进行中」并给出**已等待**时长（明细自动刷新）。任务看着"卡住"时据此判断：**长时间停在同一次尝试 = 阻塞在这单次请求**；出现第 2、3 次尝试 = 正在自动纠错重试。

> 调用时限：单次 AI 调用（含自动纠错重试）最多等待 **5 分钟**，超时会断开连接并记为「超时」，任务随即失败——不会无限期卡住。
>
> 数据边界：明细只存在本机数据库，滚动保留**最近 30 天且最多 1 万条**（应用启动时清理）；密钥从不写入明细。想看某次扩充/翻译的原文或排查 AI 报错时，先来这里。

## 6. 密钥与合规

- 所有密钥（大模型 Key、检索 Key、邮箱授权码、短信 Secret）**加密保存在本机**数据目录；界面、日志、导出中一律不回显明文。
- 所有外部调用（AI/检索/抓取/发送）都由你手动触发；除这些调用携带的必要数据外，业务数据不离开本机。
- 抓取默认遵守 robots.txt，单站 ≥1 秒间隔；发送按通道限额节流。
- 退订/拒绝的对象务必登记到黑名单——这既是合规要求，也是送达率保障。
- **备份**：设置 → 备份与数据生成归档（含全部业务数据与配置）；重新安装/换机时用「恢复」还原。建议每周一次（应用会在超过 7 天未备份时提醒）。

## 7. 常见问题

| 现象 | 处理 |
|---|---|
| 挖不到域名 | 检查检索渠道是否启用并可测试通过；种子先审核采纳；关键词换更具体的行业词 |
| 候选域名混入毫不相关的站点（酒店/旅游/字典等） | 检索渠道返回了"幌子结果"（风控替换页）。系统已能识别并判该渠道受阻，不再入库；存量数据先在候选域名「命中」列溯源（哪条 query、哪次任务），到 设置 → 检索渠道 测试并修复渠道后再重跑 |
| 抓到的邮箱很少 | 正常现象：部分站点不公开邮箱；可人工在客户详情补录，或换更垂类的种子 |
| AI 功能灰置/提示未配置 | 设置 → 大模型服务添加并测试；离线场景全部功能可手工完成（S12） |
| SMTP 测试失败 | 确认使用的是「授权码」；核对端口与加密方式（465=SSL，587=STARTTLS）；发件域策略 |
| 发送被暂停/停止 | 查看监控页提示：常见为通道每日额度用尽或账号被限流。剩余记录保持"待发"；额度按 UTC 零点恢复后（北京时间早 8 点）**重新点「启动」**即断点续发 |
| Linux 报 WebView 加载失败 | `sudo apt install python3-gi gir1.2-webkit2-4.1` 后重启应用 |
| 代理环境下打不开界面 | 应用已自动让回环地址绕过系统代理；仍异常时检查企业代理是否强制劫持 127.0.0.1 |
| 图谱视图上看不到某节点 | 结构视图只显示产品线/客户角色/市场，实体视图只显示机构/市场；被"停用"的节点不显示。切换视图或检查节点状态 |
| AI 扩充/翻译的产出找不到 | AI 与检索的产出默认都在"待审核"：种子在「待审核」页、节点/词表在「图谱管理」；另注意种子列表默认只筛"已采纳" |
| 想确认某次 AI 到底发了什么 / 返回了什么 | 顶栏「任务」→ 该 AI 任务的「调用明细」；AI 扩充完成后对话框里也有「查看调用明细」。含每次尝试的耗时与失败原因（保留最近 30 天 / 1 万条，见 5.6） |
| AI 任务长时间转圈、像卡住了 | 打开该任务的「调用明细」：停在同一次尝试且「进行中 · 已等待」持续变长 = 卡在这单次请求（最多 5 分钟会自行中断并记为超时）；出现第 2、3 次尝试 = 正在自动纠错重试。对话框里的「已等待」秒数也随时可见 |
| 挖掘任务无法启动（提示未配置检索渠道） | 设置 → 检索渠道添加并启用（免密钥渠道也可）；另确认所选种子已采纳、状态为待执行 |
| 检索渠道健康显示"异常" | 按最近失败原因处置：限流→稍后再试；风控封禁→调整优先级或更换渠道；网络→检查代理；密钥/额度→检查凭证与余额 |
| 回灌后种子产量没更新 | 回灌按**搜索词精确匹配**归因；核对回灌文件的 `seed_query` 与库内种子的搜索词是否完全一致（未匹配项在报告里列出） |
| 改过内容后计划里选不到了 | 修改已发布版本会自动退回草稿：在「营销内容」重新发布后计划才能选用 |

## 8. 反馈与诊断包

出现异常时：把数据目录下 `logs/` 中最近的日志文件（滚动文件日志）与问题描述一起反馈。日志已做密钥脱敏，可安全分享。
